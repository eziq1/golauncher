# 主界面接收文件（R97）

> 状态：✅ 已实现（待合并）。需求见 [requirements.md](requirements.md) R97；AI 对话的附件见 [ai.md §24](ai.md)；做法和“选中的文字”一致（[selected-text.md](selected-text.md)）。

## 1. 目标

把 R91 的“输入框接收文件”扩展到主界面：主界面收到文件后，在列表最上面显示“收到的文件”分组，列出各个插件能对这些文件做的动作（问 AI、打开、打开方式、在资源管理器/访达中显示、复制路径、复制名称、压缩为 ZIP、SHA-256、复制图片……），输入文字可以筛选这些动作。

## 2. 用户看到的

- **三种方式把文件交给主界面**：
  - 把文件拖到启动器窗口（停在主界面时）；
  - 在主界面按 `Ctrl+V`（macOS `⌘V`）：剪贴板里是复制的文件，或者一张图片（截图、浏览器里复制的图片；图片和文字同时在时按 R96 的规则判断，见 [ai.md §24.8](ai.md)）；是文字时照常粘贴到搜索框；
  - 在主界面按 `Ctrl+O`（`⌘O`），或者搜索“选择文件…”（`builtin.files` 的根项目）打开系统的文件选择框，可以多选。选中项自己的动作用了 `Ctrl+O` 时（例如包管理器的“打开主页”），那个动作优先。
- **“收到的文件”分组**：在列表最上面（在“选中的文字”和“在 <文件夹>”之前），每一行是一个动作，按插件给的 `Score`（明确的首选，例如“问 AI”）再按插件顺序排列。没有输入文字时最多显示 12 行。
- **文件卡片**：和 AI 对话的附件一样，在列表下面、页脚上面一排卡片：图片显示缩略图，其他文件显示图标；下面是大小（文件夹写“文件夹”）；`×` 移除这一个文件，移除最后一个就回到普通的主界面。
- **输入文字**：分组里只剩和文字匹配的动作（标题、关键字的模糊匹配；带 `Score` 的项目按它的分数算匹配，例如“问 AI：<你输入的话>”），分组仍然在最上面，下面照常是普通的搜索结果。
- **`Esc`**：搜索框有文字时先清空文字；没有文字时先清掉收到的文件，再按一次才隐藏窗口。
- **什么时候清掉**：窗口隐藏时（保留的界面例外：隐藏时停在一个 `KeepOnHide` 的界面上，例如从“问 AI”打开的对话，回来按 `Esc` 回到主界面时文件还在）、`Reset` 回到主界面时、新的文件交进来时（替换，不累加）。
- **没有插件能处理**（所有提供动作的插件都关掉了）：提示“这里不能使用这些文件”，不保留。

## 3. SDK：`plugin.FileActionsProvider` 和 `PermFiles`

和 `SelectionProvider`/`PermSelection` 一样：只有声明了 `files` 权限、实现了 `FileActionsProvider` 的插件才会看到文件的路径。

```go
const PermFiles Permission = "files"

type FileKind string // image, text, document, archive, audio, video, folder, other

type FileInfo struct {
    Path      string   // 绝对路径；粘贴的图片是宿主写的临时文件
    Name      string   // 显示的名字（粘贴的图片是“粘贴的图片.png”）
    Size      int64    // 字节；文件夹为 0
    Dir       bool     // 文件夹
    Kind      FileKind // 按扩展名判断，不读内容
    MediaType string   // 按扩展名，例如 "image/png"；不知道时为 ""
    Pasted    bool     // 从剪贴板粘贴的图片：Path 在隐藏后删除，动作要立即用完
}

type FilesQuery struct {
    Files  []FileInfo
    Source FilesSource // drop / paste / dialog
    Text   string      // 主界面里输入的文字
}

type FileActionsProvider interface {
    FileItems(ctx context.Context, q FilesQuery) ([]Item, error)
}
```

- 宿主给项目加上 `Group`（“收到的文件”），并标记 `Transient`（不进“最近使用”）和 `Sensitive`（不给 AI 工具看）；动作需要的路径要放进动作自己的 `Target`/`Payload`。
- `Score` 的含义和选中文字相同：没有输入时排序（大的在前），有输入时带 `Score` 的项目按这个分数当作匹配。
- 只有进程内（内置）插件会被调用；外部插件的协议里没有这个方法（以后和 `selectionItems` 一起加）。
- `FileReceiver` 不再在主界面被调用：以前“拖到主界面会打开新的 AI 对话”改为 AI 插件在分组里提供的第一个动作“问 AI”。`FileReceiver` 只接收 `View.AcceptFiles` 的界面里的文件（不变）。

## 4. 宿主

- **core**：`Controller` 保存这次显示收到的文件（`rootFiles`：文件信息、来源、宿主写的临时文件）。`ReceiveFiles` 在主界面时：粘贴的图片写成临时文件，`os.Stat` 读大小和是否文件夹，按扩展名判断类型（**不读文件内容**），最多 100 个，然后刷新主界面。`PasteFiles` 在主界面也可以用；`ActionChooseFiles` 从主界面的项目运行（用户自己的操作）时把选中的文件交给主界面；`Ctrl+O` 在主界面（选中项没有用这个快捷键时）打开选择框。`RemoveChip` 在主界面移除一个文件。`Snapshot.Chips` 在主界面是这些文件的卡片（`Snapshot.AcceptFiles` 只表示界面声明了接收文件，主界面不设置，所以原来的 golden 不变）。
- **主界面搜索**：`fileEntries` 并发调用各个提供者（和选中文字一样有超时），分组放在最前；有输入时只保留匹配的。
- **临时文件**：粘贴到主界面的图片写到缓存目录的 `pasted\<随机>\粘贴的图片.png`（0600）。文件被清掉 1 分钟后删除（留一点时间给刚用它打开的程序），程序退出时立即删除；新的粘贴会顺便删掉超过一天的残留。
- **日志**：只记数量和来源（`root files`），不记名字、路径、内容。
- **ui**：主界面也接管 `Ctrl+V`（探测到文件或图片时）和 `Ctrl+O`；卡片一排复用 R91 的。搜索栏高度不变（R74 的测试照常）。
- **glctl**：`session drop` 在主界面就是交给主界面；`session choose` + `key Ctrl+O`（或 `action` 运行“选择文件…”）；`session remove-chip file:0`。文本输出的分组和 `chips:` 行照常。

## 5. 内置插件提供的动作

| 插件 | 动作 | 条件 |
|------|------|------|
| AI（`builtin.ai`） | “问 AI：<文件名>”/“问 AI 这 N 个文件”，打开新对话，文件在草稿里（首选，`Score` 1）；输入文字后“问 AI：<文字>”，带着文件直接发送 | AI 开着；关着时一行“打开 AI 以询问这些文件”，打开提示界面，文件留在草稿里 |
| 文件（`builtin.files`） | 打开；打开方式…（Windows）；在资源管理器/访达中显示；复制路径（第二个动作复制文件本身）；复制名称；压缩为 ZIP；复制 SHA-256；复制图片 | 打开方式只对一个文件（不是文件夹）；ZIP 不用于粘贴的图片；SHA-256 只对一个普通文件；复制图片只对一个 PNG（包括粘贴的图片）；粘贴的图片不提供显示位置、复制路径、复制名称 |

计算器、网页搜索不提供（对文件没有合理的动作）。

## 6. 隐私

- 不读任何文件的内容，除非你选择的动作要读（例如 SHA-256、问 AI 时 AI 插件准备附件）。
- 只有声明了 `files` 权限的内置插件能看到路径；项目不给 AI 工具看，不进“最近使用”。
- 窗口隐藏就清掉（见 §2）；粘贴的图片按 §4 删除。
- 日志里只有数量。
