# Action Ring 方案

> 状态：方案 v1 · 已确认 · 第一期已实现（§8）· 2026-10-21（你的决定：按住中键 300ms 触发；**功能默认开启**；圆环 4 个固定 + 4 个情境操作按方案；分期按 §6） · 对应需求 R116（见 [requirements.md](requirements.md)）
>
> 需求：增加一个 Action Ring（参考 Logitech Options+ 的 Actions Ring）：按鼠标中键弹出一圈操作，用情境感知（R25）展示当前可用的操作。

## 1. 用起来的样子

```
                 ▶ 播放/暂停
       📁 打开终端           📝 新建笔记
  😀 Emoji         ×            ✨ 问 AI
       ⬚ 截图               🔒 锁屏
                 ⚙ golauncher
```

- 在鼠标所在位置弹出一个圆环，最多 8 个按钮，中间是关闭按钮。
- **两种用法都支持**：
  - **按住中键 → 往某个方向拖 → 松开**：直接执行那个方向的操作（像 Logitech 和游戏里的轮盘，最快）；
  - **按住到弹出后松开** → 圆环留在屏幕上 → 再用鼠标点一个，或按数字键 1–8，Esc 或点圆环外关闭。
- 圆环出现时不抢走当前窗口的焦点：选中文字、当前窗口都还在，操作才能作用在它们上面。
- 鼠标移到某个按钮上时，外面显示它的名称（和图里一样的标签）。

## 2. 触发方式：不能直接吃掉中键

中键在很多程序里本来就有用：浏览器里**新标签页打开链接、关闭标签页、自动滚动**，终端和编辑器里粘贴，CAD 软件里平移视图。如果"按一下中键就弹出"并拦截这次点击，这些都会坏。

| 触发方式 | 说明 | 建议 |
|---|---|---|
| **按住中键约 0.3 秒**（默认） | 短按的中键照常传给程序（新标签页、关标签页都不受影响）；按住不放超过阈值才弹出圆环 | ✅ 默认 |
| Ctrl/⌘ + 中键 | 按住修饰键再点中键 | 可选 |
| 鼠标侧键（前进/后退键） | 不和中键冲突，但会占用浏览器的前进/后退 | 可选 |
| 键盘快捷键 | 在鼠标位置弹出，适合没有中键的触控板 | 可选 |

**按住中键的实现细节**：中键按下时先不放行，计时：
- 0.3 秒内松开 → 原样补发一次中键点击（按下 + 松开），程序收到的就是一次普通中键点击；
- 超过 0.3 秒 → 弹出圆环，这次按下不再传给程序；
- 按住中键拖动（比如浏览器的自动滚动、CAD 的平移）→ 一旦移动超过几个像素就立刻放行，不弹圆环。

**例外名单**：游戏、CAD、远程桌面、虚拟机等中键是核心操作的程序，可以在设置里加进例外名单，在它们里面完全不拦截。默认名单里预置常见的（远程桌面、VMware、Blender 等），全屏游戏默认也不拦截。

## 3. 圆环里显示什么

圆环有 8 个位置，分成两部分：

1. **固定操作**（用户自己挑，默认 4 个）：任何地方都显示，位置固定，方便形成肌肉记忆。默认：
   - 呼出 golauncher；
   - 问 AI；
   - 截图（调用系统截图：Windows 的 Win+Shift+S，macOS 的 ⌘⇧4）；
   - 锁屏。
2. **情境操作**（其余位置，自动填）：根据鼠标下面或前台的程序、选中的内容，从现有插件里挑最相关的：

| 情境 | 举例 |
|---|---|
| 有选中的文字（R63） | 翻译、AI 操作（包括你自定义的 AI 操作，R103）、网页搜索、复制 |
| 资源管理器 / 访达（R25） | 在这里打开终端、用 VS Code 打开、复制路径、新建文件 |
| 浏览器 | 用 AI 总结当前页（如果能拿到地址）、复制链接、在另一个浏览器打开 |
| 正在播放媒体 | 播放/暂停、下一首 |
| 其他 | 用户为某个程序单独配置的操作 |

情境操作复用现有插件的情境感知和选中文字的能力，插件不用为圆环单独写代码。用户也可以给某个程序单独配一组操作（"在微信里时显示这 4 个"）。

## 4. 设置（设置 › Action Ring，新的一页）

- 开关（**默认开启**；macOS 没有"辅助功能"权限时不工作，设置页提示去授权，不在启动时弹窗）
- 触发方式（§2）和按住的时长
- 固定操作：从所有命令和动作里挑，拖动排序
- 情境操作：开 / 关，最多几个
- 每个程序单独的操作
- 例外名单
- 外观：大小、跟随主题（深浅色、强调色）

## 5. 技术实现

| 部分 | Windows | macOS |
|---|---|---|
| 监听中键 | 低级鼠标钩子 `WH_MOUSE_LL`，跑在独立线程，回调必须很快返回（系统会摘掉超过约 300 毫秒的钩子） | `CGEventTap` 监听 `otherMouseDown/Up`，需要"辅助功能"权限（选中文字已经在用这个权限） |
| 补发短按的中键 | `SendInput` | `CGEventPost` |
| 圆环窗口 | MyGo 窗口：无边框、透明、置顶、不在任务栏、不抢焦点（`Frameless`、`Transparent`、`AlwaysOnTop`、`SkipTaskbar`、`Focusable: false`） | 同左（`Panel`） |
| 情境 | 鼠标下方的窗口（`WindowFromPoint`）+ 现有的情境感知 | 现有的情境感知 |

- 钩子只处理中键，其他鼠标事件原样放行，不记录、不保存任何鼠标轨迹。
- 已知限制：Windows 上以管理员身份运行的程序，普通权限的钩子收不到它窗口里的鼠标事件；在这类窗口里圆环不会弹出。
- 圆环的绘制、拖动方向判断、动画都在 MyGo 里做，跟随主题。

### 8.2 钩子和补发

- **Windows**：`WH_MOUSE_LL` 跑在单独锁定的线程上，有自己的消息循环。回调里只读事件、问状态机、返回；只有中键按下时会查一下指针下面是哪个程序（`WindowFromPoint` 取根窗口，进程名按 PID 缓存 30 秒），用来判断例外。空闲时鼠标移动只读一个原子变量就放行。补发在另一个 goroutine 里用 `SendInput`，`dwExtraInfo` 标成 `GLRI`，钩子见到这个标记直接放行，不会重复处理。
- **别的程序注入的事件**（`LLMHF_INJECTED` 且不是我们的标记）一律放行、不处理：自动化工具、远程控制软件发的中键不会被扣住，也不会弹出圆环。
- **以管理员身份运行的程序**：golauncher 没有提权时，UIPI 会挡住我们补发的输入，所以指针在这类窗口上时（打不开它的进程令牌，或令牌是提权的）不拦截中键，圆环也不会弹出。
- **全屏独占的程序（游戏）**：`SHQueryUserNotificationState` 报告 `QUNS_RUNNING_D3D_FULL_SCREEN` 时不拦截；这个状态每 2 秒在后台查一次，钩子回调里不调用。
- **macOS**：会话级、插在最前面的 `CGEventTap`（可以吞掉事件），在单独的线程上跑 run loop。需要“辅助功能”权限：没有权限时根本不创建事件监听，也不弹系统提示；后台每 3 秒看一次权限，授权后自动开始。补发是复制按下时的事件、改成按下/松开、位置改成指针当前位置，在 HID 层 `CGEventPost`，`kCGEventSourceUserData` 打上标记。系统因为超时关掉事件监听（`kCGEventTapDisabledByTimeout`）时立即重新打开。macOS 没有和 `LLMHF_INJECTED` 对应的标志，所以只认得自己的补发。
- **状态机**：按下先扣住并计时；按住时长内松开 → 补发按下 + 松开；移动超过阈值（Windows 是系统拖动距离 `SM_CXDRAG` 的 2 倍，至少 8 像素；macOS 6 点）或同时按了别的键 → 立刻补发按下，之后一直放行到松开；到时间 → 弹出圆环，这次按下和松开都不再给程序。圆环在按住时被关掉（比如按了 Esc），松开同样被扣住。

### 8.3 圆环窗口和焦点

- MyGo 的公开 API 里只有浮出窗口（flyout）有 `Focusable: false`，普通窗口没有，所以没有直接用这个选项（**和方案的出入**）：圆环是一个 `Panel`、`Frameless`、`Transparent`、`AlwaysOnTop`、`SkipTaskbar` 的窗口，用 `ShowInactive` 显示；Windows 上再给它加 `WS_EX_NOACTIVATE`，点它也不会变成前台窗口。macOS 上 Panel 本来就不激活 golauncher，前台 App 一直是用户的；点圆环时面板可能成为键盘窗口，但前台 App 和它的选中文字不变。
- 窗口不拿键盘，所以 **1–8 和 Esc 是圆环显示期间临时注册的全局快捷键**，关掉圆环就注销（和方案的出入：方案没说怎么收键）。点圆环外面关闭也是靠钩子：圆环打开时钩子会看左右键按下的位置，在圆环窗口外就关掉（这次点击照常给程序）。
- **定位**：以指针为中心，超出屏幕时推回工作区。Windows 上用 `SetWindowPos` 按物理像素放（MyGo 的坐标跟着窗口当前所在显示器的 DPI 换算，跨显示器时不准），尺寸按那台显示器的 DPI 算，显示后再放一次，防止跨 DPI 时被系统改尺寸。macOS 用 MyGo 的点坐标。被推回时圆环中心不在指针上，选格子按圆环自己的中心算。
- **样子**：跟随主题的背景、强调色和文字色（深浅色都行）；8 个圆形按钮，中间是 ×；悬停或拖向某个按钮时，外面显示带数字键的名称标签。打开时有 120ms 的放大淡入，系统开了“减少动态效果”就没有；关闭没有动画，直接隐藏（**和方案的出入**），这样操作在圆环消失后立刻执行。
- **位置**：固定操作占上、右、下、左四个方向，情境操作占斜向四个；数字键 1–8 从正上方开始顺时针。

### 8.4 情境操作怎么选

- 情境用**指针下面的窗口**（Windows：`WindowFromPoint` 的根窗口），跑现有的情境识别（资源管理器的当前文件夹和选中文件、标题里的路径）。选中文字只在指针下的窗口就是前台窗口时读（焦点在那里），**只用 UI Automation / 辅助功能读取，不会模拟 Ctrl+C**（和选中文字设置里的“复制兜底”无关，按住中键时不发按键）。macOS 上情境和选中文字都取前台 App。关闭了“情境感知”时什么都不读。
- 候选是选中文字的操作（R63/R103，包括自定义 AI 操作）加上情境操作（R25），按插件给的 Score 从高到低，没有 Score 的保持插件自己的顺序；去掉：选中文字的预览行、和固定操作重复的（固定的“问 AI”和 AI 插件的“问 AI…”算重复）、破坏性操作、需要必填参数的。
- 一个都没有时（**兜底**），用最近用过的项目填（同样的规则）。
- 固定操作和情境操作按下后，圆环先隐藏，再执行。情境项在后台通过启动器的控制器执行，启动器不显示；如果操作打开了视图、表单或需要确认（比如带确认的操作），启动器就显示在那个界面。失败时发通知。
- **问 AI**：有选中文字时直接打开新对话，引用选中文字，让 AI 解释（AI 插件“问 AI”默认的指令）（**和方案的出入**：方案只说“问 AI”）；没有选中文字时打开空白的 AI 对话。
- **截图**：Windows 打开 `ms-screenclip:`（截图工具的覆盖层，和 Win+Shift+S 相同）；macOS 打开系统的“截屏”App（⌘⇧5 的工具栏），它用自己的权限截屏；打不开时退回 `screencapture -i -c`（截到剪贴板）。没有用 `screencapture` 做首选，因为 golauncher 启动它需要“屏幕录制”权限（**和方案的出入**）。
- **锁屏**：复用系统插件的“锁定”项（`builtin.system/system:lock`）。

### 8.5 设置

设置 › 操作环（新的一页，在“插件”和“高级”之间）：

- 开关（默认开）；按住时长（默认 300ms，150–1000）。
- 固定操作：列表带数字、↑ ↓、移除；“添加操作”对话框搜索所有命令和启动器能搜到的项目，以及圆环自己的三个操作；“恢复默认”先确认。最多 8 个。用按钮排序，没有做拖动排序（**和方案的出入**，和 R103 的列表一致）。
- 情境操作：开关（没有做“最多几个”，空位自动填满）。
- 例外名单：输入程序名（Windows）或 Bundle ID / App 名称（macOS）添加，逐个移除。默认名单两边的都有：mstsc、msrdc、Windows App、VNC、TeamViewer、AnyDesk、Parsec、VMware、Hyper-V（vmconnect）、VirtualBox、Parallels、UTM、Blender。
- macOS 没有辅助功能权限时，页面顶部提示，按钮打开系统设置的辅助功能页（复用“设置 › 权限”的做法）；启动时不弹窗。
- 隐私说明：只处理中键；只有按住中键或圆环打开时才看指针位置和其他按键；不记录、不保存。

第二期（§6）的触发方式、每个程序单独的操作、浏览器和媒体的情境、外观设置都还没做。

### 8.6 测试

- 状态机：短按补发、按住弹出、移动放行、同时按其他键放行、例外放行、别的程序注入的事件不处理、自己的补发不重复处理、按住时关闭仍扣住松开、过期的计时器不起作用、停止钩子时补发按下、并发（`-race`）。
- 选格子：8 个方向、22.5° 边界、死区、最远距离；窗口定位（屏幕边缘、左侧 150% 显示器、工作区比圆环小）。
- 内容：固定 + 情境、按 Score 排序、去重、空情境兜底、情境关闭；用真实的选中文字、文件和系统插件（假的系统，不会锁屏）跑一遍，并通过控制器执行“复制路径”和“锁定”。
- 界面：`mui.Tester` 测圆环（悬停显示标签、点击、数字键、Esc、×、点外面）和设置页（开关、时长校验、固定操作的移动/移除/添加/恢复、情境开关、例外的添加/去重/移除、macOS 权限提示、中文）。
- 钩子：Windows 上用假的 `MSLLHOOKSTRUCT` 测事件判断（不安装钩子）和 `INPUT` 的内存布局；安装真钩子的冒烟测试要设 `GOLAUNCHER_HOOK_TESTS=1` 才跑，默认跳过。macOS 的事件监听只交叉编译检查，需要在 Mac 上手测。
