# Action Ring 方案

> 状态：方案 v1 · 已确认 · 第一期已实现（§8）· 2026-10-21（你的决定：按住中键 300ms 触发；**功能默认开启**；圆环 4 个固定 + 4 个情境操作按方案；分期按 §6） · 对应需求 R116（见 [requirements.md](requirements.md)）
>
> 需求：增加一个 Action Ring（参考 Logitech Options+ 的 Actions Ring）：按鼠标中键弹出一圈操作，用情境感知（R25）展示当前可用的操作。

## 1. 用起来的样子

```
                 ▶ 播放/暂停
       📁 打开终端           📝 新建笔记
  😀 Emoji         ×            ✨ 问 AI
       ⬚ 截图               🔒 锁屏
                 ⚙ golauncher
```

- 在鼠标所在位置弹出一个圆环，最多 8 个按钮，中间是关闭按钮。
- **两种用法都支持**：
  - **按住中键 → 往某个方向拖 → 松开**：直接执行那个方向的操作（像 Logitech 和游戏里的轮盘，最快）；
  - **按住到弹出后松开** → 圆环留在屏幕上 → 再用鼠标点一个，或按数字键 1–8，Esc 或点圆环外关闭。
- 圆环出现时不抢走当前窗口的焦点：选中文字、当前窗口都还在，操作才能作用在它们上面。
- 鼠标移到某个按钮上时，外面显示它的名称（和图里一样的标签）。

## 2. 触发方式：不能直接吃掉中键

中键在很多程序里本来就有用：浏览器里**新标签页打开链接、关闭标签页、自动滚动**，终端和编辑器里粘贴，CAD 软件里平移视图。如果"按一下中键就弹出"并拦截这次点击，这些都会坏。

| 触发方式 | 说明 | 建议 |
|---|---|---|
| **按住中键约 0.3 秒**（默认） | 短按的中键照常传给程序（新标签页、关标签页都不受影响）；按住不放超过阈值才弹出圆环 | ✅ 默认 |
| Ctrl/⌘ + 中键 | 按住修饰键再点中键 | 可选 |
| 鼠标侧键（前进/后退键） | 不和中键冲突，但会占用浏览器的前进/后退 | 可选 |
| 键盘快捷键 | 在鼠标位置弹出，适合没有中键的触控板 | 可选 |

**按住中键的实现细节**：中键按下时先不放行，计时：
- 0.3 秒内松开 → 原样补发一次中键点击（按下 + 松开），程序收到的就是一次普通中键点击；
- 超过 0.3 秒 → 弹出圆环，这次按下不再传给程序；
- 按住中键拖动（比如浏览器的自动滚动、CAD 的平移）→ 一旦移动超过几个像素就立刻放行，不弹圆环。

**例外名单**：游戏、CAD、远程桌面、虚拟机等中键是核心操作的程序，可以在设置里加进例外名单，在它们里面完全不拦截。默认名单里预置常见的（远程桌面、VMware、Blender 等），全屏游戏默认也不拦截。

## 3. 圆环里显示什么

圆环有 8 个位置，分成两部分：

1. **固定操作**（用户自己挑，默认 4 个）：任何地方都显示，位置固定，方便形成肌肉记忆。默认：
   - 呼出 golauncher；
   - 问 AI；
   - 截图（调用系统截图：Windows 的 Win+Shift+S，macOS 的 ⌘⇧4）；
   - 锁屏。
2. **情境操作**（其余位置，自动填）：根据鼠标下面或前台的程序、选中的内容，从现有插件里挑最相关的：

| 情境 | 举例 |
|---|---|
| 有选中的文字（R63） | 翻译、AI 操作（包括你自定义的 AI 操作，R103）、网页搜索、复制 |
| 资源管理器 / 访达（R25） | 在这里打开终端、用 VS Code 打开、复制路径、新建文件 |
| 浏览器 | 用 AI 总结当前页（如果能拿到地址）、复制链接、在另一个浏览器打开 |
| 正在播放媒体 | 播放/暂停、下一首 |
| 其他 | 用户为某个程序单独配置的操作 |

情境操作复用现有插件的情境感知和选中文字的能力，插件不用为圆环单独写代码。用户也可以给某个程序单独配一组操作（"在微信里时显示这 4 个"）。

## 4. 设置（设置 › Action Ring，新的一页）

- 开关（**默认开启**；macOS 没有"辅助功能"权限时不工作，设置页提示去授权，不在启动时弹窗）
- 触发方式（§2）和按住的时长
- 固定操作：从所有命令和动作里挑，拖动排序
- 情境操作：开 / 关，最多几个
- 每个程序单独的操作
- 例外名单
- 外观：大小、跟随主题（深浅色、强调色）

## 5. 技术实现

| 部分 | Windows | macOS |
|---|---|---|
| 监听中键 | 低级鼠标钩子 `WH_MOUSE_LL`，跑在独立线程，回调必须很快返回（系统会摘掉超过约 300 毫秒的钩子） | `CGEventTap` 监听 `otherMouseDown/Up`，需要"辅助功能"权限（选中文字已经在用这个权限） |
| 补发短按的中键 | `SendInput` | `CGEventPost` |
| 圆环窗口 | MyGo 窗口：无边框、透明、置顶、不在任务栏、不抢焦点（`Frameless`、`Transparent`、`AlwaysOnTop`、`SkipTaskbar`、`Focusable: false`） | 同左（`Panel`） |
| 情境 | 鼠标下方的窗口（`WindowFromPoint`）+ 现有的情境感知 | 现有的情境感知 |

- 钩子只处理中键，其他鼠标事件原样放行，不记录、不保存任何鼠标轨迹。
- 已知限制：Windows 上以管理员身份运行的程序，普通权限的钩子收不到它窗口里的鼠标事件；在这类窗口里圆环不会弹出。
- 圆环的绘制、拖动方向判断、动画都在 MyGo 里做，跟随主题。

### 8.2 钩子和补发

- **Windows**：`WH_MOUSE_LL` 跑在单独锁定的线程上，有自己的消息循环。回调里只读事件、问状态机、返回；只有中键按下时会查一下指针下面是哪个程序（`WindowFromPoint` 取根窗口，进程名按 PID 缓存 30 秒），用来判断例外。空闲时鼠标移动只读一个原子变量就放行。补发在另一个 goroutine 里用 `SendInput`，`dwExtraInfo` 标成 `GLRI`，钩子见到这个标记直接放行，不会重复处理。
- **别的程序注入的事件**（`LLMHF_INJECTED` 且不是我们的标记）一律放行、不处理：自动化工具、远程控制软件发的中键不会被扣住，也不会弹出圆环。
- **以管理员身份运行的程序**：golauncher 没有提权时，UIPI 会挡住我们补发的输入，所以指针在这类窗口上时（打不开它的进程令牌，或令牌是提权的）不拦截中键，圆环也不会弹出。
- **全屏独占的程序（游戏）**：`SHQueryUserNotificationState` 报告 `QUNS_RUNNING_D3D_FULL_SCREEN` 时不拦截；这个状态每 2 秒在后台查一次，钩子回调里不调用。
- **macOS**：会话级、插在最前面的 `CGEventTap`（可以吞掉事件），在单独的线程上跑 run loop。需要“辅助功能”权限：没有权限时根本不创建事件监听，也不弹系统提示；后台每 3 秒看一次权限，授权后自动开始。补发是复制按下时的事件、改成按下/松开、位置改成指针当前位置，在 HID 层 `CGEventPost`，`kCGEventSourceUserData` 打上标记。系统因为超时关掉事件监听（`kCGEventTapDisabledByTimeout`）时立即重新打开。macOS 没有和 `LLMHF_INJECTED` 对应的标志，所以只认得自己的补发。
- **状态机**：按下先扣住并计时；按住时长内松开 → 补发按下 + 松开；移动超过阈值（Windows 是系统拖动距离 `SM_CXDRAG` 的 2 倍，至少 8 像素；macOS 6 点）或同时按了别的键 → 立刻补发按下，之后一直放行到松开；到时间 → 弹出圆环，这次按下和松开都不再给程序。圆环在按住时被关掉（比如按了 Esc），松开同样被扣住。

### 8.3 圆环窗口和焦点

- MyGo 的公开 API 里只有浮出窗口（flyout）有 `Focusable: false`，普通窗口没有，所以没有直接用这个选项（**和方案的出入**）：圆环是一个 `Panel`、`Frameless`、`Transparent`、`AlwaysOnTop`、`SkipTaskbar` 的窗口，用 `ShowInactive` 显示；Windows 上再给它加 `WS_EX_NOACTIVATE`，点它也不会变成前台窗口。macOS 上 Panel 本来就不激活 golauncher，前台 App 一直是用户的；点圆环时面板可能成为键盘窗口，但前台 App 和它的选中文字不变。
- 窗口不拿键盘，所以 **1–8 和 Esc 是圆环显示期间临时注册的全局快捷键**，关掉圆环就注销（和方案的出入：方案没说怎么收键）。点圆环外面关闭也是靠钩子：圆环打开时钩子会看左右键按下的位置，在圆环窗口外就关掉（这次点击照常给程序）。
- **定位**：以指针为中心，超出屏幕时推回工作区。Windows 上用 `SetWindowPos` 按物理像素放（MyGo 的坐标跟着窗口当前所在显示器的 DPI 换算，跨显示器时不准），尺寸按那台显示器的 DPI 算，显示后再放一次，防止跨 DPI 时被系统改尺寸。macOS 用 MyGo 的点坐标。被推回时圆环中心不在指针上，选格子按圆环自己的中心算。
- **样子**：跟随主题的背景、强调色和文字色（深浅色都行）；8 个圆形按钮，中间是 ×；每个按钮外侧都显示带数字键的名称标签（R117 起始终显示，见 §8.7）。打开时有 120ms 的放大淡入，系统开了“减少动态效果”就没有；关闭没有动画，直接隐藏（**和方案的出入**），这样操作在圆环消失后立刻执行。
- **位置**：固定操作占上、右、下、左四个方向，情境操作占斜向四个；数字键 1–8 从正上方开始顺时针。

### 8.4 情境操作怎么选

- 情境用**指针下面的窗口**（Windows：`WindowFromPoint` 的根窗口），跑现有的情境识别（资源管理器的当前文件夹和选中文件、标题里的路径）。选中文字只在指针下的窗口就是前台窗口时读（焦点在那里），按选中文字设置读取，和启动器弹出时一样：先用 UI Automation / 辅助功能，开了“复制兜底”时也会模拟 Ctrl+C（R131 起；之前按住中键时不发按键，浏览器里弹出时读不到文字，情境操作就退回成最近用过的操作）。macOS 上情境和选中文字都取前台 App。关闭了“情境感知”时什么都不读。
- **指针下的项目**（R120）：在资源管理器、桌面、访达里，情境跟着指针下的项目走（和右键菜单一样：没选中的项目只针对它，选中集合里的项目针对整个集合，空白处针对当前文件夹），在圆环窗口盖住指针之前读取，不改动选中状态，见 [context-awareness.md](context-awareness.md) §12。
- 候选是选中文字的操作（R63/R103，包括自定义 AI 操作）加上情境操作（R25），按插件给的 Score 从高到低，没有 Score 的保持插件自己的顺序；去掉：选中文字的预览行、和固定操作重复的（固定的“问 AI”和 AI 插件的“问 AI…”算重复）、破坏性操作、需要必填参数的。
- 一个都没有时（**兜底**），用最近用过的项目填（同样的规则）。
- 固定操作和情境操作按下后，圆环先隐藏，再执行。情境项在后台通过启动器的控制器执行，启动器不显示；如果操作打开了视图、表单或需要确认（比如带确认的操作），启动器就显示在那个界面。失败时发通知。
- **问 AI**：有选中文字时直接打开新对话，引用选中文字，让 AI 解释（AI 插件“问 AI”默认的指令）（**和方案的出入**：方案只说“问 AI”）；没有选中文字时打开空白的 AI 对话。
- **截图**：Windows 打开 `ms-screenclip:`（截图工具的覆盖层，和 Win+Shift+S 相同）；macOS 打开系统的“截屏”App（⌘⇧5 的工具栏），它用自己的权限截屏；打不开时退回 `screencapture -i -c`（截到剪贴板）。没有用 `screencapture` 做首选，因为 golauncher 启动它需要“屏幕录制”权限（**和方案的出入**）。
- **锁屏**：复用系统插件的“锁定”项（`builtin.system/system:lock`）。

### 8.5 设置

设置 › 操作环（新的一页，在“插件”和“高级”之间）：

- 开关（默认开）；按住时长（默认 300ms，150–1000）。
- 固定操作：列表带数字、↑ ↓、移除；“添加操作”对话框搜索所有命令和启动器能搜到的项目，以及圆环自己的三个操作；“恢复默认”先确认。最多 8 个。用按钮排序，没有做拖动排序（**和方案的出入**，和 R103 的列表一致）。
- 情境操作：开关（没有做“最多几个”，空位自动填满）。
- 例外名单：输入程序名（Windows）或 Bundle ID / App 名称（macOS）添加，逐个移除。默认名单两边的都有：mstsc、msrdc、Windows App、VNC、TeamViewer、AnyDesk、Parsec、VMware、Hyper-V（vmconnect）、VirtualBox、Parallels、UTM、Blender。
- macOS 没有辅助功能权限时，页面顶部提示，按钮打开系统设置的辅助功能页（复用“设置 › 权限”的做法）；启动时不弹窗。
- 隐私说明：只处理中键；只有按住中键或圆环打开时才看指针位置和其他按键；不记录、不保存。

第二期（§6）的触发方式、每个程序单独的操作、浏览器和媒体的情境、外观设置都还没做。

### 8.6 测试

- 状态机：短按补发、按住弹出、移动放行、同时按其他键放行、例外放行、别的程序注入的事件不处理、自己的补发不重复处理、按住时关闭仍扣住松开、过期的计时器不起作用、停止钩子时补发按下、并发（`-race`）。
- 选格子：8 个方向、22.5° 边界、死区、最远距离；窗口定位（屏幕边缘、左侧 150% 显示器、工作区比圆环小）。
- 内容：固定 + 情境、按 Score 排序、去重、空情境兜底、情境关闭；用真实的选中文字、文件和系统插件（假的系统，不会锁屏）跑一遍，并通过控制器执行“复制路径”和“锁定”。
- 界面：`mui.Tester` 测圆环（悬停显示标签、点击、数字键、Esc、×、点外面）和设置页（开关、时长校验、固定操作的移动/移除/添加/恢复、情境开关、例外的添加/去重/移除、macOS 权限提示、中文）。
- 钩子：Windows 上用假的 `MSLLHOOKSTRUCT` 测事件判断（不安装钩子）和 `INPUT` 的内存布局；安装真钩子的冒烟测试要设 `GOLAUNCHER_HOOK_TESTS=1` 才跑，默认跳过。macOS 的事件监听只交叉编译检查，需要在 Mac 上手测。

### 8.7 R117：透明窗口和名称标签（2026-10-22）

- **窗口改成 Flyout（Windows）**：MyGo 在 Windows 上只给有材质的窗口和 Flyout 去掉重定向位图（`WS_EX_NOREDIRECTIONBITMAP`），内容透明的地方才透出桌面；普通的透明 `Panel` 留着位图，透明处画成黑色，Windows 11 又给 Panel 加了圆角和描边，所以第一期的圆环外面是一块黑色圆角矩形。现在圆环是**托盘模式的 Flyout**（`mygo.NewFlyout`，`Tray` 是 golauncher 的托盘图标，没有父窗口，`WS_EX_TOPMOST` 盖在其他程序上）：`Focusable: false`（`WS_EX_NOACTIVATE`，点击时 `MA_NOACTIVATE`，不抢焦点），**不要阴影**（这样不调用 `roundFlyout`，没有圆角和描边），根背景 `Transparent`，圆盘自己仍是主题色。
- **定位**：MyGo 只在创建时、`SetSize`/`SetAnchor` 时和父窗口移动时摆放 Flyout（挨着托盘图标）；显示（`ShowInactive`）不会重新摆放，托盘 Flyout 也没有父窗口。圆环从不调用这些，所以创建后照旧由 `placeRing` 用 `SetWindowPos` 按物理像素放到指针中心、推回工作区，显示后再放一次。
- **关闭**：不可聚焦的 Flyout 不会因为点外面或切换窗口自己关（`ShouldClose` 只对可聚焦的 Flyout 起作用）；Esc 没被内容处理时 MyGo 会关闭 Flyout，和 Panel 一样走 `OnClose`，那里阻止关闭、改成 `closeRing`。其余行为不变：临时全局快捷键 Esc 和 1–8、钩子判断点外面关闭、焦点不动、圆环隐藏后再执行操作。
- 托盘图标创建失败时退回第一期的 Panel（会有黑底），日志里有警告。
- **macOS 不变，仍用 Panel**：macOS 的透明窗口本来就是 `setOpaque:NO` + 透明背景色，没有黑底问题；Panel 带 `canJoinAllSpaces`，在当前空间（包括全屏 App 的空间）显示，而 MyGo 的 Flyout 不加这个，换空间后可能显示在别的空间，所以 macOS 上不换。
- **名称标签**：参考 Logitech Options+，每个按钮外侧**始终**显示一个名称标签（带数字键），按方向排：右侧的从圆盘边上向右（左对齐），左侧的向左（右对齐、贴着圆盘），正上方和正下方的居中；斜向的标签和按钮同高，并算好离圆盘的距离，不压到圆盘。指到或拖向的按钮用强调色，它的标签描边和数字键变成强调色、文字加粗；指到标签也算指到那个按钮，点击标签执行它。标签最宽 180 DIP，过长的名称以“…”结尾，悬停标签显示完整名称的提示。窗口相应加大到 652×344 DIP（照旧推回工作区）。
- **图标**：“在此处打开命令提示符”和系统工具里“以管理员身份打开命令提示符”改用 `square-terminal`（方框里的提示符），和终端的 `>_` 区分开。其他仍然相同的图标靠始终显示的标签区分。
- 测试：`internal/shell/ring_test.go` 检查窗口选项（Windows 上是托盘 Flyout、不可聚焦、无阴影；macOS 是透明无边框无阴影的 Panel）；`internal/ui/ring_test.go` 检查所有标签不悬停也显示、高亮跟随悬停/拖动/指到标签、标签都在窗口里且不压圆盘不互相重叠、左右对齐和居中、长名称截断和提示。透明效果本身没法在测试里看到桌面合成，**需要在 Windows 上实测确认**。

### 8.8 R119：问 AI 和选中文字（2026-10-22）

## 9. 鼠标钩子拖慢系统输入（R122，2026-10-22）

**现象**：开着 golauncher 时，Windows 上打字会变慢、丢键，所有程序都这样；退出 golauncher 就好了。出问题前用过圆环、选中过文字。在机器上跑构建和测试时也会出现。

**原因**：Windows 用同一个线程（RIT）按顺序处理鼠标和键盘输入，每个鼠标事件都要等低级鼠标钩子（`WH_MOUSE_LL`）返回，才处理下一个事件。golauncher 的钩子回调是 Go 代码，每个事件（包括每一次鼠标移动）都要进入 Go 运行时。golauncher 进程忙的时候，回调要排队等到空闲的 P 才能运行。忙的情况包括：读选中文字、垃圾回收、AI 输出、索引刷新，以及构建和测试把所有 CPU 核占满。鼠标事件因此积压，排在后面的键盘事件也跟着变慢、丢失。系统超时移除钩子只针对单次回调超过 `LowLevelHooksTimeout` 的情况；几十毫秒的慢回调不会被移除，会一直拖着。

**实测**（临时实验程序，约 500 Hz 注入鼠标移动，4 秒）：

| 钩子所在进程 | 进入回调的延迟 | 处理的事件数 |
|---|---|---|
| 空闲 | 0（最长 16 ms，为计时精度） | 约 1600 |
| 同一进程里有 CPU 和内存分配负载（相当于现在的 golauncher） | p99 31～94 ms，最长 125 ms | 95～216（下降到空闲时的 1/7～1/16） |
| 独立的空闲进程，**另一个进程**占满 CPU | 最长 16 ms | 和空闲时一样 |
| 同上，钩子线程设为 `THREAD_PRIORITY_TIME_CRITICAL` | 最长 16 ms | 和空闲时一样 |

**修法**：钩子移到一个只做这件事的小进程里（`golauncher --mouse-hook-host`，只在 Windows 上）。
- 状态机 `ring.Machine` 也在这个进程里运行，因为吞不吞中键必须在钩子里同步决定。同样在这里运行的还有：判断是否允许弹出（`AppAt`、全屏检测、例外名单）和重放中键（`SendInput`）。
- 两个进程之间用标准输入输出逐行传 JSON。主进程发给钩子进程：开关圆环（SetOpen）、按住时长、例外名单、Reset。钩子进程发给主进程：Open、Track（只发最新一个）、Release、Press。钩子线程只把消息放进队列，从不等管道写完。
- 钩子线程调高到最高优先级。
- 主进程退出或管道断开（标准输入读到 EOF）时，钩子进程卸掉钩子并退出；另外用作业对象（Job，关闭时结束其中的进程），保证主进程崩溃时它也会被结束。
- 钩子进程启动失败时，记一条警告，退回进程内钩子，圆环照常可用。
- macOS 的 `CGEventTap` 不在这次范围内：系统发现事件监听太慢会直接关掉它，不会拖慢输入。

**测试建议**：要模拟按键、抢前台窗口、装真钩子的真机测试（`GOLAUNCHER_HOOK_TESTS`、`GOLAUNCHER_SELECTION_TESTS`、`GOLAUNCHER_CLIPBOARD_TESTS` 等）默认都不会运行，开发时只在用户不用电脑时才设这些变量。

### 9.1 实现记录（2026-10-22）

- **钩子进程**：`golauncher --mouse-hook-host`，在 `cmd/golauncher/main.go` 最开头处理，不经过单实例、配置、日志、安装器和界面。入口 `mousehook.HostMain`（`internal/winapi/mousehook/host_windows.go`），协议和主循环在 `host.go`。进程里跑真正的 `ring.Machine` 和原来的 `WH_MOUSE_LL`：判断是否允许弹出（`AppAt`、全屏、例外名单 `ring.Excluded`）、补发中键（`SendInput`）、拖动阈值都和进程内时一样；钩子线程设为 `THREAD_PRIORITY_TIME_CRITICAL`。指针在主进程的窗口上时，和以前一样当作 golauncher 自己（不去打开进程令牌）。
- **钩子线程不等管道**：回调只把事件放进队列（预先分配、最多 64 条，满了丢弃），由单独的 goroutine 写到标准输出；Track 只保留最新的一个，并保持在其他事件之间的顺序。事件手写成 JSON（`strconv`），不分配内存；状态机不需要的鼠标移动只读一个原子变量就放行，不加锁、不分配（有测试检查 0 次分配）。钩子进程启动后的堆约 3 MB（全部来自程序里各个包的初始化），之后几乎不再分配，GC 可以忽略。
- **协议**（每行一个 JSON，未知的行和字段忽略）：
  - 主进程 → 钩子进程：`hold`（按住时长，毫秒）、`exceptions`（例外名单）、`open`（圆环关闭/显示，带 `seq`）、`reset`（带 `seq`）、`start`（安装钩子；按住时长和例外名单在它之前发，钩子不会在没有设置的情况下运行）。
  - 钩子进程 → 主进程：`ready` / `error`（钩子装好了 / 装不上）、`open`（带 `seq`）、`track`、`release`（`moved`）、`press`（`middle`）、`button`（中键是否处于被状态机处理的按下中，即 `Machine.ButtonDown`，“问 AI”等它松开再复制要用）。
  - **状态机自己会改 `open`**：按住到时间时它自己把圆环设为打开（就是 `open` 事件）；关闭只由主进程发起（`SetOpen(false)`、`Reset`）。主进程每次关闭都把 `seq` 加一，钩子进程发 `open` 时带上它已经执行到的最后一次关闭的 `seq`；主进程收到的 `seq` 比自己的小，说明这次打开会被随后的关闭撤销，直接丢弃——和原来同一进程里 `openRing` 发现 `Machine.Open()` 为 false 时不显示一样。
- **主进程这边**：`mousehook.Remote`（`remote.go`）。`internal/shell/ring.go` 里新加接口 `ringMachine`（`Open`、`ButtonDown`、`SetOpen`、`SetHold`、`Reset`），进程内的 `ring.Machine`（macOS、退回时）和 `Remote` 都满足；`ringRemote` 再加上 `SetExceptions` 和 `Start`。`Remote` 保存 `open`（收到 `open` 事件为 true，`SetOpen(false)`/`Reset` 为 false）和 `ButtonDown` 的副本；读管道的 goroutine 调用的回调和以前一样只往主线程投递（`ringPost`），不阻塞。`syncRing` 的按住时长和例外名单会转发过去。`WindowAt`、`RootOwner`、`AppAt` 在主线程上用的仍在主进程里直接调用。
- **生命周期**：用 `os.Executable()` 启动自己，`CREATE_NO_WINDOW`，放进 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的作业对象（和插件进程共用 `internal/winapi/proc` 的 `NewKillOnCloseJob`，原来 `extproc` 里的那份改为调用它）。关掉圆环或退出时关闭它的标准输入：它停掉钩子，把还扣着的中键按下补发给程序（退出前同步发送），然后退出；2 秒内没退出就结束它。主进程崩溃时，管道断开或作业对象关闭也会让它结束。
- **退回**：钩子进程启动失败（5 秒内没有 `ready`，或报告 `error`）→ 记一条警告，改用进程内钩子。运行中意外退出 → 警告，关闭圆环，重启一次；再退出就改用进程内钩子，不会反复重启。
- **macOS 不变**，仍在进程内。
- **测试**：用内存管道把 `Remote` 和真正的主循环 `runHost` 接起来，假的钩子和时钟（不安装钩子）：设置在安装钩子之前到达、例外放行、短按补发、按住打开 / Track / 拖动松开、`ButtonDown` 跟随、关闭后的打开被丢弃（`seq`）、停止时补发扣着的按下、启动失败、意外退出后可以再启动；队列合并 Track 和顺序、事件编码往返和 0 分配、空闲时鼠标移动 0 分配；`shell` 里用假的 `ringRemote` 测启动、关闭、启动失败退回、意外退出重启一次后退回。真正启动钩子进程的 `TestRealHost` 和 `TestRealHook` 一样要设 `GOLAUNCHER_HOOK_TESTS=1`。**需要实测**：开着 golauncher 跑构建时打字是否恢复正常，圆环、短按、拖动、例外和“问 AI”是否照常。

## 10. macOS 触控板：三指轻点打开圆环（R127，2026-10-22）

**问题**：Mac 触控板没有中键，按住中键的触发方式用不了。

**你的选择**：在 §2 列的方案（A 全局快捷键、B 修饰键加按住点击、C 触控板手势）里选 C。

**手势**：**三指轻点**，即三根手指几乎同时轻触触控板再抬起，不按下去。圆环在指针位置弹出，并停留，和“按住中键、不拖动就松开”一样：点一个操作、按 1–8，或 Esc、点外面关闭。
- 判定：三根手指在约 80 ms 内先后落下，全部抬起前最多 3 根，从第一根落下到全部抬起不超过约 300 ms，每根手指的位移很小，期间没有物理按下。
- 不做重按（Force Touch）：压力事件只发给指针下的程序，全局监听收不到。
- 不做三指按住：会和辅助功能的“三指拖移”冲突。

**实现**：系统不公开触控板的原始触点，用私有的 `MultitouchSupport.framework` 读取（`MTDeviceCreateList`、`MTRegisterContactFrameCallback`、`MTDeviceStart`），通过 purego 调用，不需要 cgo。BetterTouchTool、MiddleClick 等软件用的是同一套接口。回调在框架自己的线程上执行，只做判定，判定成立后把“在指针位置打开圆环”交给主线程，不阻塞。
- 打开圆环走现有的 `openRing` 和“停留”状态，例外名单、全屏检测和中键一样生效（按最前面的程序判断）。
- 框架加载失败或接口不在时，这个手势静默关闭并记一条日志，中键照常可用。
- 外接妙控板（Magic Trackpad）同样生效，插拔设备后重新枚举。

**冲突**：如果在 系统设置 › 触控板 里打开了“查询与数据检测器：三指轻点”，系统也会响应同一个手势；设置页提示这一点。

**设置**：设置 › Action Ring 增加“三指轻点触控板打开圆环”开关（只在 macOS 上显示），默认开启。

**验证**：开发机是 Windows，只能交叉编译和单元测试判定逻辑（用合成的触点帧）；真机行为要你在 Mac 上实测。

### 10.1 实现记录（2026-10-22）

- **代码在哪**：新包 `internal/trackpad`。`touch.go` 解码触点、`tap.go` 判定三指轻点，都是纯 Go、和平台无关；`trackpad_darwin.go` 通过 purego 调用 `MultitouchSupport.framework`；`trackpad_other.go` 是其他平台的空实现（`Supported` 为 false）。接线在 `internal/shell/ring.go`（`syncTrackpad`、`ringTapped`），状态机加了 `ring.Machine.OpenAt`，配置是 `ring.trackpadTap`（默认 true）。
- **接口（ABI）**：私有框架，没有官方头文件。参考公开的逆向资料（Erling Ellingsen 2008 年的 multitouch.c、MiddleClick 的头文件、OpenMultitouchSupport 的 `MTTouch`，MIT），只用来确认内存布局，代码是自己写的。回调是 `void cb(MTDeviceRef, MTTouch *touches, size_t n, double timestamp, size_t frame)`；purego 的回调只声明前三个整数参数（amd64 和 arm64 上它们都在前三个整数寄存器里，double 走浮点寄存器），时间戳和帧号不读；个数按 32 位读，`int` 和 `size_t` 两种声明都对。每个触点 96 字节，amd64 和 arm64 相同：标识 @16、状态 @20、归一化坐标 x @32、y @36（float32，0–1），其余字段在 `touch.go` 的注释里逐个列出偏移。状态 3（MakeTouch）和 4（Touching）算手指在板上，悬停、抬起、离开都不算。
- **线程**：框架在自己的线程上回调。回调里只解码（固定大小的数组，不分配内存）、在锁内喂这台设备的 `Tap`，判定成立时调 `onTap`；shell 传入的 `onTap` 只是 `ringPost(ringTapped)`，不阻塞。主线程上 `ringTapped` 取指针位置（MyGo 的屏幕坐标，和事件监听的点坐标一致），调用 `Machine.OpenAt`：和按住中键一样，先用 `Allowed`（最前面的程序、例外名单、全屏）判断，再通过 `Open` 回调走 `openRing`。圆环打开后状态机处于“停留”状态（空闲 + 打开），点外面、中键点选、1–8、Esc 都和按住中键松开后一样。圆环已经打开或中键正按着时，三指轻点不起作用。
- **判定**（常量都在 `tap.go`）：3 根手指；后面的手指在第一根落下后 80 ms 内落下（`TapDownWindow`）；全部抬起前出现第 4 根（或抬起后又落下一根）就不算；从第一根落下到全部抬起不超过 300 ms（`TapMaxDuration`）；每根手指离落点不超过 0.04（归一化，约 4–6 mm，`TapMaxMove`）；必须有 3 根同时在板上。不算的手势要等所有手指抬起才重新开始判定，所以三指扫动（调度中心、切换空间）和三指拖移不会触发。
- **物理按下**：没有用事件监听（它空闲时不看左右键），而是在判定成立时用公开的 `CGEventSourceSecondsSinceLastEventType`（HID 系统状态）查左键、右键、其他键最近一次按下的时间；在手势期间或手势开始前 80 ms 内有按下就不算。
- **开关**：只在圆环开启、钩子在运行（macOS 上就是有辅助功能权限）并且设置打开时运行；关掉圆环、没有权限、关掉设置或退出时停止。框架或任何一个函数找不到时，记一条 Info 日志，之后不再尝试，中键照常可用。
- **设备插拔**：用 IOKit 的匹配通知（`AppleMultitouchDevice` 的 FirstMatch 和 Terminate，在单独的线程上跑 run loop）得知设备接入或移除，等 500 ms 后停掉所有设备、重新枚举并启动。开机时没有触控板（例如 Mac mini）也会等到接入妙控板时开始工作。
- **设置**：设置 › 操作环，按住时长下面加“三指轻点触控板打开操作环”开关，只在 macOS 上显示（有权限宿主时），说明里提示“查询与数据检测器：用三指轻点”的冲突。macOS 的隐私说明加了一句读取触控板触点（`settings.ring.privacy.text@darwin`）。中英文都有。
- **测试**：`internal/trackpad/tap_test.go` 用合成帧测判定（连续两次轻点、两指、四指、抬起一根后再落一根、第三根太晚、按住太久、抬起太晚、上扫和横扫、三指拖移、单指滑动、三指不同时在板上、只有悬停、小幅抖动仍算、期间有物理按下不算、喂帧 0 次分配）和按文档偏移拼出的字节解码；`ring` 测 `OpenAt`（停留状态、已打开时不再打开、中键按着时不打开、例外不打开）；`shell` 用假的 `trackpad.Start` 测开关条件、打开、关闭、框架不可用时只试一次；`ui` 测开关只在 macOS 显示、切换、中文。真机测试 `TestRealTrackpad` 要设 `GOLAUNCHER_TRACKPAD_TESTS=1`：列出设备，记录 10 秒的触点帧和识别到的轻点，不注入任何输入。
- **需要在 Mac 上实测**：结构布局和回调参数（看真机测试里的坐标是否在 0–1、标识是否稳定）；判定的阈值手感；打开“轻点来点按”或“三指拖移”时三指轻点会不会产生鼠标按下（会的话手势被当成点击而不触发）；妙控板和妙控鼠标（也是多点触控设备，同样会响应）；插拔妙控板、睡眠唤醒后是否还能用（唤醒后不会重新枚举，如果失效需要补）；带触控栏的机型上触控栏是否也在设备列表里。
## 11. 圆环弹出时也用复制兜底（R131，2026-10-23）

**现象**：在 Windows 终端里选中文字打开圆环，情境格子是 5 个 AI 操作；在浏览器等需要复制才能读到文字的地方，情境格子却是别的（最近用过的操作）。

**原因**：终端支持 UI Automation，圆环弹出时就读到了文字。按 §5 和 R119 的设计，圆环弹出时（中键还按着）只用 UI Automation 读、不发按键，要等选了需要文字的操作、中键松开后才复制；浏览器网页的选区 UI Automation 读不到，弹出那一刻程序不知道有选中文字，情境格子只能退回成最近用过的操作。

**修法**：圆环弹出时经 `selectionReader` 按选中文字设置读取，**复制兜底和启动器弹出时一样生效**（指针在前台窗口上时才读）。理由：被拦下的中键按下从没交给程序，圆环窗口从不抢焦点，模拟的 Ctrl+C 和没有圆环时一样发给前台窗口。复制在主线程外完成，固定操作先显示，情境格子在读到文字后补上；读取预算（`ringContextBudget`）在 Windows 上从 400 ms 放宽到 800 ms，留出复制的时间。弹出时已经复制过，选中操作后就不再复制一次（`ringCapture.read`）。浏览器里 UI Automation 读空时退回复制的规则（R130）在这里同样生效。

**测试**：`TestRingOpenCopies`（只能复制读到文字的程序：弹出时复制并读到文字、记为已读；复制兜底关时不复制）；`TestSelectionOnePath` 改为三处（启动器、圆环弹出、选中操作后）都带复制兜底。
