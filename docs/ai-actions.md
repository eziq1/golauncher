# 自定义 AI 操作方案

> 状态：方案 v1 · 已确认（§8 四项都按建议执行），第一期已实现（待合并，见 §9） · 2026-10-18 · 对应需求 R103（见 [requirements.md](requirements.md)）
>
> 需求：现在选中文字后的 AI 操作是固定的，希望用户能在 AI 插件的配置页面自定义 AI 操作。对应 Raycast 的"AI Commands"。

## 1. 现状

- 选中文字后的 AI 操作写死在 `plugins/ai/selection.go`：翻译成〈语言〉、问 AI…、解释、总结（选中至少 200 字时才出现）、改写、建议回复；输入文字时多一行"AI 处理选中文字：〈文字〉"。
- 提示词是代码里的英文常量；所有操作都用同一个图标；每个操作都是**打开 AI 对话**，替换选中文字是对话里的"粘贴"动作（Ctrl+Shift+V）。
- 没输入文字时，宿主最多显示 6 个操作（`maxSelectionRows`）。
- 设置页没有"结构化列表"的编辑器：偏好只有文本、密码、数字、开关、下拉、多行列表、路径、快捷键、按钮。AI 插件的"后端"和"AI 工具"两节是宿主为 AI 插件单独画的。

## 2. 用起来的样子

**设置 › 插件 › AI › AI 操作**（新的一节，放在"后端"之后）：

```
AI 操作                                         [新建操作] [恢复默认]
 ☑ 翻译成〈界面语言〉   内置   选中文字          [编辑] [↑] [↓]
 ☑ 解释                内置   选中文字          [编辑] [↑] [↓]
 ☑ 总结                内置   选中文字 ≥200 字   [编辑] [↑] [↓]
 ☑ 改写                内置   选中文字          [编辑] [↑] [↓]
 ☑ 建议回复            内置   选中文字          [编辑] [↑] [↓]
 ☑ 改成正式邮件         自定义 选中文字·直接出结果 [编辑] [↑] [↓] [删除]
 ☐ 代码审查            自定义 选中文字、文件      [编辑] [↑] [↓] [删除]
```

- 勾选框控制是否启用；顺序就是列表里出现的顺序（没输入文字时只显示前 6 个，输入文字会在全部操作里筛选）。
- 内置操作可以改名、改提示词、停用、调顺序，但不能删；"恢复默认"把内置操作恢复原样，自定义操作不受影响。
- "问 AI…"和"AI 处理选中文字：〈文字〉"是通用入口，不进这个列表，始终保留。

**编辑一个操作**（弹出对话框）：

| 字段 | 说明 |
|---|---|
| 名称 | 列表里显示的标题，例如"改成正式邮件" |
| 提示词 | 多行文本，可用占位符（见 §3） |
| 用于 | 选中文字 / 主输入框收到的文件（R97）/ 两者都要 |
| 结果 | **打开对话**（现在的做法，可以接着追问）或 **直接出结果**（见 §4） |
| 关键词 | 可选，便于输入筛选 |
| 图标 | 从内置图标里选，默认 ✨ |
| 最少字数 | 可选，选中文字少于这个数时不显示（"总结"用的就是这个，默认 200） |

## 3. 提示词占位符

| 占位符 | 内容 |
|---|---|
| `{selection}` | 选中的文字（超长时截断并注明，和现在一样） |
| `{lang}` | 目标语言，按 R65 的规则（设置里的"翻译成"，或界面语言；原文已经是目标语言时改成英文） |
| `{input}` | 在启动器里输入的文字（可选的补充要求） |
| `{app}` | 选中文字所在的应用名（环境感知打开时才有） |
| `{date}` | 今天的日期 |

提示词里没有 `{selection}` 时，按现在的做法把选中文字以引用块附在提示词后面。用于文件时，文件按 R91 的附件发给 AI。

## 4. "直接出结果"模式

适合改写、润色、翻译这类"要的就是结果"的操作：

- 选中操作后，启动器里显示一个**结果视图**，流式显示 AI 的回答，不显示对话气泡。
- Enter：替换选中的文字（选中文字可编辑时）或粘贴到前一个窗口；Ctrl+C 复制；Tab 转成普通对话，接着追问；Esc 返回。
- 背后仍是一次普通对话，会保存在 AI 对话历史里（保留天数按现有设置）。

## 5. 存储与隐私

- 操作列表存在 `config.json` 里 AI 插件的偏好下（键 `actions`，JSON），方便备份和以后导入导出；提示词不是机密，不进凭据管理器。
- 内置操作只保存用户改过的字段（名称、提示词、是否启用、顺序），没改过的跟随新版本的默认值。
- 发送规则不变：只有用户点了操作才发送选中文字；AI 工具（MCP）看不到这个列表。

## 6. 实现要点

- `plugins/ai`：把固定的操作改成"内置默认 + 用户覆盖 + 自定义"合并后的列表，`SelectionItems` 和 `FileItems` 都从它生成；新增结果视图。
- 设置页：宿主在 AI 插件页里再画一节（和"后端"一样的做法），编辑对话框复用设置窗口的表单控件；校验名称不为空、提示词不为空。
- 测试：合并规则（内置被改、被停用、版本新增内置操作）、占位符替换、R65 目标语言、6 行上限和排序、"直接出结果"的替换和粘贴（假后端、假剪贴板）、设置页的增删改和上下移动（`mui.Tester`）、glctl golden。

## 7. 分期

| 期 | 内容 |
|---|---|
| **一** | 设置页的"AI 操作"一节（新建、编辑、删除、启用、排序、恢复默认）；占位符；用于选中文字和文件；"打开对话"和"直接出结果"两种结果 |
| **二** | 每个操作可以作为命令出现在根搜索，单独设别名和快捷键（例如按一个快捷键直接对当前选中文字运行"改成正式邮件"）；导入、导出（JSON）；每个操作指定后端或模型 |

## 9. 实现记录（第一期，2026-10-18）

### 9.1 做了什么

| 部分 | 位置 | 说明 |
|---|---|---|
| 数据模型 | `plugins/ai/actions`（新包） | `Action`（名称、提示词、用于、结果、关键词、图标、最少字数、停用）；`Stored` 是偏好 `actions` 的 JSON：`order`（和默认顺序不同时才存）、`builtin`（内置操作改过的名称/提示词/停用）、`custom`（自定义操作）。`Merge` 合并、`Diff` 反算要存的内容、`Restore` 恢复默认、`Move`、`NewID`（`custom-<n>`）、`Check` 校验、`Expand` 替换占位符（一次替换，替换进去的文字不会再被展开）。`Provider` 接口由 AI 插件实现，`app.Env.AIActions` 拿到它（和 `AIBackends` 同样的做法） |
| 合并规则 | 同上 | 内置操作没改过的字段跟随新版本；`order` 里没有的内置操作（以后版本新增的）插在默认顺序里它前一个内置操作的后面；新版本删掉的内置操作消失；自定义操作不能用内置操作的 ID |
| 选中文字的操作 | `plugins/ai/aiactions.go`、`selection.go` | `SelectionItems` 从合并后的列表生成：只取启用的、用于选中文字的、满足最少字数的，按列表顺序；"问 AI…"固定插在第一个操作之后（和以前一样排第二），有输入时"让 AI 处理选中的文字"排第一。最多 7 行仍由宿主控制 |
| 文件的操作 | `plugins/ai/files.go` | 用于文件（或两者都要）的操作排在"问 AI：<文件>"后面，文件按 R91 的附件发送，`{selection}` 为空 |
| 占位符 | `aiactions.go` | 提示词里没有 `{selection}` 和 `{input}` 时在生成条目时就替换好，放进原来的 `instruction` 字段，所以内置操作的 payload、发送内容和 glctl golden 都和以前完全一样；有这两个占位符时 payload 带 `prompt` 和 `vars`（lang/app/date），打开时再替换。`{lang}` 用 R65 的 `translateTarget`（发给模型用英文语言名，标题里用界面语言名）；`{app}` 是选中文字所在程序名去掉 `.exe`；`{date}` 是 `YYYY-MM-DD` |
| 直接出结果 | `aiactions.go` `renderResult`、`chat.go` | 和对话是同一个视图 ID、同一套对话运行时，`chat.result` 为真时换一种画法：只显示回答（流式，带光标），没有对话气泡。Enter = 粘贴（选中文字可编辑时标题是"替换选中的文字"），Ctrl+C 复制，Tab（回调 `tochat`）把 `result` 关掉变回普通对话，Tab 前输入的文字作为追问发出，Esc 用宿主默认的返回。保存在对话历史里，从历史打开就是普通对话 |
| 设置页 | `internal/ui/actions_settings.go` | "后端"之后的"AI 操作"一节：每行有启用勾选框、图标、标题、内置/自定义标记、"选中文字 · 至少 200 字 · 打开对话"这样的说明，编辑、↑、↓，自定义的还有删除；上方"新建操作""恢复默认"（先确认）。编辑用 `mui.Modal` 对话框；内置操作只能改名称和提示词（其余字段不显示）。每次改动立即写入 `config.json` |
| glctl | `internal/cli` | 新增 `--pref <插件>:<名称>=<JSON>`（可重复，只在假环境里），用来在会话和查询里设置 AI 操作 |
| 文案 | 插件文案在 `plugins/ai/locales`，设置页文案在 `internal/i18n/locales` | 中英文都有 |

### 9.2 与方案的出入

- `{input}`：方案写的是"在启动器里输入的文字"。但输入文字时是在筛选操作，所以改为：提示词里有 `{input}` 的操作带一个可选参数（Tab 进入参数框，和"问 AI…"一样），参数的值就是 `{input}`。
- "问 AI…"的位置：固定排在第一个操作之后，保证默认的行和以前一模一样。
- 结果视图没有新的视图 ID，而是对话视图的另一种画法，这样对话运行时、保存、隐藏后恢复都不用改。
- 结果视图写回答时 Enter 是"停止"（回答还没出来，没有东西可以粘贴）；Esc 直接返回，回答在后台写完照样存进历史。
- 内置操作的标题是模板，"翻译"在设置页显示为"翻译成{lang}"。标题里也可以用 `{lang}` `{app}` `{date}`。
- 图标从 15 个内置图标里选（下拉框，旁边显示图标本身）。
- 内置操作的"停用"只存 `disabled: true`；方案说"只保存改过的字段"，这里一致。
