# 计时器与提醒插件设计方案

> 状态：已实现（待合并），见 §9 · 2026-10-15 · 对应需求 R48（见 [requirements.md](requirements.md)）
>
> 需求：新增插件：计时器与提醒，如 `timer 25m`，结束时发通知。

## 1. 定位

内置插件 `builtin.timer`（`plugins/timer`），纯 Go 实现，只用 SDK（`pkg/plugin`）。两类条目：

- **倒计时**（timer）：从现在起计一段时长，`timer 25m`；
- **定时提醒**（reminder）：到某个时刻提醒，`remind 15:30 开会`；`remind in 20m 喝水` 也算提醒（只是用时长表示）。

两者在内部是同一种记录：一个**绝对的结束时刻**（墙上时间）加上总时长、标签、是否暂停。区别只在文案（"计时结束" / "提醒"）和能做的操作（提醒不能"重新开始"）。

动态显示沿用世界时钟的做法（[world-clock.md §3](world-clock.md)）：根搜索里每秒 `Host.Invalidate`，"计时器"视图每秒 `Host.Render`，窗口隐藏就停。

## 2. 输入

### 2.1 前缀

| 偏好 | 默认值 | 说明 |
|------|--------|------|
| `prefixes` | `["timer", "计时", "倒计时"]` | 倒计时 |
| `remindPrefixes` | `["remind", "提醒"]` | 定时提醒 |

规则和世界时钟一样：ASCII 前缀后面必须是空格或结尾（`timers` 不会触发 `timer`）；以汉字结尾的前缀后面可以直接接内容（`计时25分钟`、`提醒明天9点交周报`）。两组前缀都匹配时取最长的（`倒计时` 优先于 `计时`）。不带前缀的输入不返回结果，不干扰普通搜索。默认不带 `t`：太短，会和应用名冲突，用户可以自己加。

### 2.2 时长（倒计时）

`timer <时长> [标签]`，时长也可以放在最后：`timer 喝水 25m`。

| 写法 | 例子 |
|------|------|
| 单位组合（可以有空格、小数） | `25m`、`1h30m`、`1h 30m`、`90s`、`1.5h`、`2h5m10s` |
| 英文单位全称和缩写 | `25 min`、`25 minutes`、`1 hour 30 minutes`、`30 sec`、`2 hrs` |
| 钟表形式 | `25:00`（分:秒）、`1:30:00`（时:分:秒） |
| 只有数字 | `timer 25` 按分钟 |
| 中文 | `25分钟`、`25分`、`1小时30分钟`、`1小时30分`、`5分30秒`、`90秒`、`1.5小时`、`1个小时`、`半小时`、`一个半小时`、`1个半小时`、`一刻钟`、`三刻钟`、`十分钟`、`两小时`、`二十五分钟` |

- 中文数字支持 零一二两三四五六七八九十百（到 999），可以和阿拉伯数字混用。
- 范围：大于 0，不超过 7 天（`7d`、`7天` 也可以写）。超出范围、写错（`timer 25x`、`timer abc`）都不是时长：不出预览条目，只按标签筛选正在运行的计时器。
- 标签是时长之外剩下的文字（去掉首尾空格）。

### 2.3 时刻（提醒）

`remind [日期] <时刻> [标签]`，或 `remind in <时长> [标签]`、`提醒 <时长>后 [标签]`。

| 部分 | 写法 |
|------|------|
| 日期 | `today` `tomorrow` `今天` `明天` `后天` `今晚`；星期 `mon`…`sun`、`monday`…、`周一`…`周日`（`周天`）、`星期一`…`星期日`（`星期天`）；`下周一`；`2026-10-20`；`10月20日`、`10月20号` |
| 时刻 | `15:30`、`9:00`、`9am`、`9:30pm`、`9 am`、`12pm`（中午）、`12am`（午夜）；`9点`、`9点半`、`9点30`、`9点30分`、`9点一刻`、`15时30分`；前面可以加 `上午` `早上` `凌晨` `中午` `下午` `晚上` `今晚`（下午/晚上把 1–11 点加 12） |
| 可以省略的词 | 开头的 `me` `at` `on`（`remind me at 3pm to call mom`）、`我` `在`（`提醒我明天9点交周报`）；标签开头的 `to` 和 `提醒我` `提醒`（`明天9点提醒我交周报`） |

- **没有日期、时刻今天已经过了**：改到明天，预览里写明"今天 15:30 已过，改为明天"。写了 `今天`/`today` 的也一样。
- **写了日期、没有时刻**：默认 9:00，预览里写明。
- **星期**：下一个这一天；就是今天且时刻还没到时，是今天。`下周一` 是下一周的周一。
- **写了具体日期且已经过了**：不出条目。
- 没有日期也没有时刻、或者时刻不合法（`25:00`、`9点70`）：不出条目。

`timer` 前缀下也接受 `in`/`后` 以外的时刻吗？不接受：`timer 15:30` 是 15 分 30 秒。

### 2.4 预览条目

输入能解析时，第一条是预览，`Enter` 开始：

- 倒计时：标题 `开始 25 分钟计时器` / `Start 25-minute timer`（有标签时加 `：喝水`），副标题 `将于 15:42 结束`。
- 提醒：标题 `提醒：开会`（没有标签时 `在 15:30 提醒`），副标题 `今天 15:30 · 5 小时 30 分后`；改到明天时副标题写明原因。

动作的载荷只存解析后的输入（时长或原始文字），**执行时再按当时的时间计算**结束时刻。这样从"最近使用"里再次执行也是从那一刻起算（和世界时钟复制动作的做法一样）。

## 3. 列表

### 3.1 根搜索

- `timer`（或 `remind`）后面什么都没写：列出**正在运行和暂停的**计时器，然后是**预设**（番茄钟 25 分钟、短休息 5 分钟、长休息 15 分钟），再是**最近用过的**（历史里去重后的最近 5 个时长 + 标签）。
- 写了不能解析的文字：只列出标签包含这段文字的计时器。
- 分组标题"计时器"。条目预打分：预览 1，计时器从 0.9 递减，预设和最近的更低（排名不会被"最近使用"加分顶上去）。

### 3.2 "计时器"视图（命令 `timers`）

分段：正在运行（含暂停）、预设、最近（历史：已结束和已取消的）。搜索框同时是输入框：输入 `25m 喝水` 时第一段是"新建"预览，其余按标签筛选。

### 3.3 每一条

| 部分 | 内容 |
|------|------|
| 标题 | 剩余时间加标签：`24:13  喝水`；没有标签时 `24:13  25 分钟计时器` / `24:13  提醒` |
| 副标题 | 运行中：`15:42 结束`（不是今天的写日期）；暂停：`已暂停 · 剩余 12:30` |
| 附注 | 进度百分比 `52%`；暂停时 `已暂停` |
| 图标 | `timer`（倒计时）、`alarm-clock`（提醒）、暂停时 `pause`；新增这三个 SVG |
| 详情 | 标签、开始时间、结束时间、总时长、剩余、进度 |

剩余时间超过 1 小时写 `1:05:03`，否则 `24:13`。

### 3.4 操作

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 暂停 / 继续 | `Enter` | 暂停时记下剩余时长；继续时结束时刻 = 现在 + 剩余 |
| 加 5 分钟 | `Ctrl+Enter` | 已经结束的不能加（见历史的"稍后再提醒"） |
| 加 1 分钟 | — | |
| 重新开始 | `Ctrl+R` | 从总时长重新计时（只有倒计时） |
| 重命名 | — | 表单视图，改标签 |
| 复制结束时间 | `Ctrl+Shift+C` | |
| 取消 | `Ctrl+X` | 不需要确认；取消的进历史，可以"恢复"（撤销） |
| 打开计时器视图 | — | 只在根搜索里 |

历史条目：`再来一次`（同样时长和标签，倒计时）、`稍后再提醒`（5 分钟后，同样标签）、`恢复`（取消的，剩余时长按取消时的算）、`从历史中移除`。预设和最近条目：`Enter` 开始。

**AI**（[ai.md §4.2、§16](ai.md)）：开始、暂停、继续、取消、加时、重命名都是 `Callback`，不标 `ReadOnly`，AI 调用前会问用户；查看计时器是打开视图（`Push`），直接执行。取消不标 `StyleDestructive`（需求是不需要确认，而且能恢复）。

## 4. 到点通知

- 用 `Host.Toast`：启动器可见时显示在底栏，不可见时发 Windows 通知（宿主现有的通道，和后台任务一样）。点击通知打开启动器。
- 文案：倒计时 `计时结束：喝水`，正文 `25 分钟 · 15:42 结束`；提醒 `提醒：开会`，正文 `15:30`。
- **错过的**（结束时刻已经过了 1 分钟以上才发现：golauncher 当时没运行、电脑在睡眠）：正文写 `本应在 15:30 提醒`。
- **声音**：偏好 `sound`（默认开）。宿主新增 `Toast.Silent`（SDK 字段，JSON `silent`），Windows 通知按它决定是否静音（MyGo 的 `NotificationOptions.Silent`）。底栏的 Toast 本来就没有声音。
- **通知上的按钮**（"+5 分钟""关闭"）：MyGo 的通知不支持按钮，**这一期不做**；替代办法是到点后历史里的"稍后再提醒"。
- **底栏指示灯**：宿主的指示灯是后台任务专用的，没有通用机制；加一个通用机制改动不小，**这一期不做**，记为待定。

## 5. 调度与正确性

- **存储**：插件 KV 的一个键 `state`（JSON）：下一个 ID、正在运行的列表、历史列表。每次变化都整体写回。时间以 RFC 3339 存储，时长以毫秒存储。
- **绝对时刻**：结束时刻是墙上时间，存储和比较都去掉 Go 的单调时钟读数（`Round(0)`），所以重启、睡眠、改系统时间后，都按墙上时间判断。
- **调度循环**：一个 `Host.Go` 的 goroutine。有计时器在运行时，等到最早的结束时刻（加 10ms 余量），但**最多等 5 秒**就重新看一次墙上时间（Go 的计时器在睡眠期间是否计时不可靠；系统时间被改也能在 5 秒内发现）。没有运行中的计时器时不轮询，只等"有变化"的信号。窗口显示（`window-shown`）时也立即检查一次。精度：正常 ≤ 1 秒（10ms 余量 + 宿主转发），睡眠唤醒或改时间后 ≤ 5 秒。
- **只通知一次**：检查到期在锁内完成：把到期的从运行列表移到历史并**先写回存储**，然后才发通知。同一个计时器不可能被检查两次（不在运行列表里了），重启后也不会再发。代价是写回之后、发通知之前进程被杀会漏发，这种情况可以接受（至多一次）。
- **启动时补发**：`Init` 读取存储；调度循环开始前先等 3 秒（`Options.StartupDelay`），让外壳先接好通知通道，然后发出启动前就到期的通知（标记为错过）。
- **暂停的计时器**不会到期；重启后仍是暂停状态。

## 7. 测试

- **解析**：英文、中文的表格测试（各种单位、钟表形式、中文数字、半小时、一刻钟、标签在前或在后、`in`/`后`、日期词、星期、`下周一`、ISO 和中文日期、上午/下午/晚上、12am/12pm、已过的时刻改到明天、已过的日期、不合法的输入不出结果也不 panic）；外加一个模糊测试（`FuzzParse`），保证任何输入都不 panic。
- **调度**（hostfake + 假时钟 + 注入的 `After`，没有真实等待）：开始、暂停、继续、取消和恢复、加时、重新开始、重命名；到点只通知一次；持久化往返（新插件实例读回）；启动时补发错过的提醒（文案带"本应在"）；时钟跳变（睡眠：假时钟直接前进 1 小时）；暂停的不会到期；历史条数上限；最多等 5 秒。
- **视图和刷新**：根搜索每秒 `Invalidate`、不带前缀/隐藏/无人拉取时停止；视图每秒 `Render`、`ViewClosed`/隐藏/`Close` 后停止；到点时 `Invalidate`。
- **glctl golden**（固定 `--now`）：`timer 25m`、`timer 1h30m 喝水`、`计时 半小时`、`remind 15:30 开会`、`提醒 明天 9点 交周报`、`timer`（空列表 + 预设），以及会话：开始一个计时器后 `timer` 列出它。
- **i18n**：`en.json` 和 `zh-CN.json`，`glctl i18n check` 通过。
- 测试里不发真实通知、不放声音（hostfake 只记录 Toast）。

### 宿主侧改动

- `internal/ui/icons.go`：新增 `timer`、`alarm-clock`、`pause` 三个图标（Lucide）。
- `internal/builtin`：`All` 和 `Fake` 各加一行 `timer.New()`。
- 文档：`plugin-guide.md`（示例表、`Toast.Silent`）、`plugin-protocol.md`（`host/toast` 的参数）。

### 与设计的差异和补充

1. **时间的 12 小时歧义**：`提醒 3点 开会` 按字面是 3:00（今天已过就是明天 3:00，预览里写明），不去猜下午。想要下午写 `下午3点` 或 `15:00`。猜测在晚上说"9点"时会弄错（是今晚还是明早），预览是更可靠的保护。
2. **时刻后面的星期**（`3pm sunday`）只认全称，`3pm sun screen` 里的 `sun` 不当作星期日；放在前面时缩写也可以（`fri 5pm`）。
3. **只写日期不写时间**：`今天`/`today` 单独写不出条目（9:00 多半已过）；`今晚`、`明晚` 默认 20:00，其余默认 9:00。
4. **取消的计时器**即使偏好"历史记录"设为 0，也保留最近一个，用于"恢复"。
5. **"计时器"视图**的搜索框里，`15:30 call` 这种既能当时长（15 分 30 秒）也能当时刻的输入，两个预览都列出（倒计时在前）；带前缀（`remind 15:30`）时只列对应的一种。
6. **根搜索**：输入能解析时，预览下面也列出正在运行的计时器；不能解析的文字只按标签筛选正在运行的计时器（历史只在视图里）。"最近用过的"只列倒计时（时长 + 标签去重，最多 5 个，不含预设）。
7. **复制结束时间**用宿主的 `CopyText`（AI 可以直接执行），暂停中的计时器没有这个操作。重命名是表单视图，提交后回到主搜索（SDK 没有"返回上一层"的结果）。
8. **进度**按整数计算（向下取整），避免浮点误差让 20% 显示成 19%。
9. **调度的测试钩子**：`checks`（检查次数）和 `idle`（正在等待），测试据此同步，不依赖真实时间；另有一个 1 秒的真实时钟测试（`TestRealClock`，`-short` 时跳过），也只记录 Toast，不弹系统通知。
10. **"最近使用"里的旧条目**：执行过的条目会被宿主记进"最近使用"（条目快照）。开始类的动作在执行时才按当时的时间计算结束时刻，所以没有问题；对已经结束的计时器执行暂停等操作时，提示"这个计时器已不存在"。
