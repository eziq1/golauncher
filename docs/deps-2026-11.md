## MyGo 0.5.5 → 0.7.4：和我们有关的变化

公开 API 只有新增，没有删改我们用到的东西（对比了模块缓存里两个版本的 `go doc -all`：`mygo`、`ui`、`ui/markdown`、`ui/markdown/parser`、`transfer`）。唯一删掉的 `CookiesModule` 我们没用；`Tray.OnClick` 只是返回值去掉了名字。所以编译没有问题，Windows 和 `GOOS=darwin CGO_ENABLED=0` 都能直接编过。

### 0.7.0 的不兼容变更，逐条对照

| 变更 | 影响我们吗 | 说明 |
|---|---|---|
| macOS 子窗口不再跟着父窗口移动 | 不影响 | 我们没有子窗口：启动器、设置、Action Ring（macOS 上是 Panel）都是独立窗口，`WindowOptions.Parent` 一个都没设。`Parent` 只用在打开/保存对话框上（设置窗口、安装程序窗口），那是 sheet，不是子窗口 |
| 中日韩应用名的默认 slug 变了 | 不影响 | slug 只给 `mygo` 命令行打包用 |
| `mygo` 命令行打出的 DMG 和 Windows 安装包按 slug 命名 | 不影响 | 我们不用 `mygo build`：Windows 用 `scripts/windows/build.ps1`（`go build` + `Compress-Archive`），macOS 用 `scripts/macos/build.sh`，release.yml 也一样（见 [macos-port.md](macos-port.md)、[self-install.md §9](self-install.md)）。zip 名仍是 `golauncher_<版本>_<os>_<arch>.zip`，本地跑 `build.ps1 -Zip` 确认过，release workflow、brewcask、wingetmanifest、`internal/update` 和 README 的链接都不受影响 |
| `audio.Player.Position` 读数变晚 | 不影响 | 不用 `mygo/audio` |

### 其他行为变化

- **（要改代码）悬停选中：行在不动的鼠标下移动时，MyGo 现在会在一两帧内改"悬停"到新的行。** MyGo 0.6 起按 Go 的值给元素做标识（我们的行按 key），重新排列后被悬停的那个元素先跟着它的 key 走一帧，下一帧再按位置重新命中鼠标下的行。我们原来的规则是"列表变了以后，第一次悬停的行不选中，之后悬停就选中"（R26/R27）——这两次悬停被拆到了两帧，于是第二次就把选中项抢走了。`TestLateSelectionWithPointerOnList`（选中文字在根列表显示 100ms 后才到、鼠标停在列表上）因此失败：预览行没被选中，选中的是鼠标下的“Rewrite”。
  修法：只有**鼠标真的动过**才让悬停选中。启动器每帧读根元素的 `PointerPosition`（`notePointer`），显示后第一次看到鼠标只记位置；之后位置变了，或从窗口外移进来，才"上膛"（`armed`）；列表内容变了照旧退膛。悬停到另一行时，上膛才选中。行为和以前一样：鼠标停着不动、列表在它下面变，不会改选中项；动一下鼠标，悬停照常选中。代价是鼠标在启动器上移动时每次都会重建一帧（以前只在悬停的元素变了时重建），启动器很小，可以接受。
- **0.7.4：Windows 上原生 UI 窗口在第一帧画好之前用 DWM cloak 藏着**，`Hidden: true` 的窗口在隐藏时就先画第一帧。启动器、设置、Action Ring 都是 `Hidden: true`，第一次显示不再闪白。cloak 只在第一帧之前，之后的显示/隐藏不受影响。`ShowInactive` 还是 `SW_SHOWNOACTIVATE`，我们的 `WS_EX_NOACTIVATE` 和 `SetWindowPos` 放置（`placeRing`）照旧。
- **0.7.2：透明的原生 UI 窗口不再有重定向位图**（#660），透明区域显示后面的内容而不是黑色。这本来是 R117 让 Windows 上的 Ring 改用托盘 flyout 的原因之一；但 Panel 仍会被 Windows 11 当工具窗口加圆角和描边，所以 flyout 还是要用。只改了 `ring_windows.go` 里过时的注释。没有托盘图标时 Ring 退回 Panel，现在透明区域也不会黑了。
- **0.6.0：WebView2 的浏览器快捷键没开 DevTools 就不生效、编辑键交给页面**：我们不显示网页（`PageOptions` 只设了 `DevTools`），不影响。
- **0.6.0：`Shell.TrashItem` 不再永久删除**：没用。
- **0.6.0：看不见的窗口不画帧**：启动器隐藏时本来就不需要画；显示时照常画。
- **0.6.0：`ui.Tester.Click`/`ClickWith`/`RightClick` 点窗口外的元素会返回错误**：我们的 UI 测试全过，没有点到窗口外的。
- **0.6.0 / 0.7.0：重新启动的程序会回到前台**：第二个实例退出前会 `AllowSetForegroundWindow`，第一个实例在 `OnSecondInstance` 里显示启动器时更容易真正拿到前台。
- **0.6.3：文本框自己接住按键，Ctrl+V 只粘贴一次**；**0.7.3（macOS）：没有文本框有焦点时，窗口级的 ⌘C/⌘V/⌘X/⌘A/⌘Z 快捷键会执行**；**0.7.4：编辑菜单跟着焦点**，焦点里的内容做不了的编辑项（比如没选中文字时的“复制”）会变灰。macOS 上 ⌘C/⌘X 在搜索框里没有选中文字时，可能会不再被编辑菜单吃掉，而是传给我们的 `OnTextKey`（AI 动作里的 Ctrl+C、任务和 AI 历史的 Ctrl+X 等动作快捷键）。需要在 Mac 上看一下（见下面的清单）。
- **0.6.4：中文、日文每个字算一个词**：搜索框里 Ctrl+Backspace / Ctrl+←→ / 双击选词在中文里按字走，不再整句。
- **0.6.0：flexbox 按 Chrome 的方式布局**、**0.7.4：grid 子元素的百分比按自己的格子算**：我们没用 grid；flex 布局的 UI 测试和 golden 都没变。
- **markdown**：0.7.0 加了 `Options.InlineMath`（行内公式作为文字里的对象画），流式时没写完的 `$…` 也按公式显示（只在 `Streaming` 下）。我们的 `mathview` 自己把行内公式换成 Unicode 文字、显示公式用 `Options.Math`，不用 `Streaming`，所以行为不变；以后可以考虑用 `InlineMath` 让行内公式也用我们的排版画。`Painter.Glyphs`、`ui.Shape` 没变。
- 渲染：0.6 起只重画变化的部分、批量绘制，0.7 起动画只重画自己。没有接口变化，但要目测一下主题和半透明效果。

## 需要手动看一下的地方

### Windows

- **悬停选中**：打开启动器时鼠标正好停在列表上，不动鼠标，等上下文（"在 <目录> 中"）和选中文字分组到达，选中项应该停在第一行；然后动一下鼠标，悬停的行应该被选中。鼠标从窗口外移进来停在某行上，也应该选中它。用滚轮滚列表、鼠标不动时，选中项不跟着变（和以前一样）。
- **第一次显示**：启动器、设置窗口、Action Ring 第一次出现时不应闪白，也不应慢一拍（DWM cloak 最多等 1 秒）。
- **Action Ring（托盘模式 flyout，R117）**：按住触发键打开，确认出现在鼠标处（`placeRing`）、多显示器/不同缩放下位置对、不抢焦点（原窗口的选区还在、打字还进原窗口）、空心处能看到下面的内容、没有黑框/圆角描边。
- **Ring 退回 Panel 时**（没有托盘图标，比如关掉托盘图标的环境）：现在透明区域应显示桌面而不是黑色，但会有 Windows 11 工具窗口的圆角描边。
- **启动器的 Acrylic/Mica 和各内置主题**：半透明、圆角、阴影、选中行、渐变背景；如有 Windows 10 机器，看一下无材质时的背景是否不透明、边缘没有白线。
- **文本输入**：搜索框里 Ctrl+V 只粘贴一次；复制文件后 Ctrl+V 进入接受文件的视图；中文里 Ctrl+Backspace 按字删。输入法候选正常。
- **设置窗口**：侧边栏切页、导入/导出对话框、窗口缩放时边缘不黑。
- **Markdown/公式**：AI 回答、插件详情里的行内和显示公式。
- **托盘菜单**：Windows 11 风格的菜单显示正常、各项能点。
- **已运行时再次启动 golauncher.exe**：启动器应显示并拿到焦点。

### macOS

- **编辑快捷键**：搜索框里没有选中文字时按 ⌘C / ⌘X：如果选中的结果有 Ctrl+C / Ctrl+X 的动作（AI 动作、任务、AI 历史），看是触发动作还是什么都不做；有选中文字时 ⌘C/⌘X/⌘V/⌘A/⌘Z 照常编辑。⌘V 粘贴文件进接受文件的视图。
- **Action Ring（Panel）**：打开位置、不抢焦点、移动/切换显示器；我们没有子窗口，0.7.0 的子窗口变化不应有影响。
- **设置窗口里的打开/保存对话框**（sheet）能正常出来、等待回答（0.7.3 修过从原生 UI 点击打开的对话框）。
- **悬停选中**同 Windows。
- **vibrancy 和主题**、空闲时的 CPU（0.7.4 说空闲窗口唤醒次数大大降低）。
