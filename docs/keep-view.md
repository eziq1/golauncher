# 隐藏后保留界面（R75）

> 状态：✅ 已实现并发布（v0.7.0）。需求见 [requirements.md](requirements.md) R75。

## 1. 问题

窗口每次隐藏（`Esc`、失去焦点、执行了会隐藏窗口的动作、复制后切到别的程序……），下次呼出都回到根搜索（`Controller.Reset`）。对 AI 对话很不方便：复制回答 → 隐藏 → 去别处粘贴 → 再呼出时得重新找到那个对话。

## 2. 方案概览

- **界面自己声明**：SDK 新增 `plugin.View.KeepOnHide`（JSON `keepOnHide`，外部插件协议直接传 `plugin.View`，所以也能用）。
- **隐藏时决定**：窗口隐藏时看**栈顶**界面最后一次返回（或推送）的 `View.KeepOnHide`。为真就记下"保留"和隐藏时间；不关闭任何界面（不发 `ViewClosed`）。
- **整栈保留**：保留整个导航栈——每一层的界面、实例 ID（`ViewRequest.Instance`）和 payload、搜索框文字（AI 对话里没发出去的草稿）、选中项、表单和参数的输入。动作面板、确认框、toast 不保留（它们本来就是一次性的）。
- **呼出时恢复**：条件都满足就恢复保留的栈；否则照旧回到根搜索，并对被丢弃的界面发 `ViewClosed`。
- **宿主设置**（设置 › 通用 › "回到主界面"）：`立即` / `10 分钟后`（默认）/ `从不`。只对声明了 `KeepOnHide` 的界面生效，其他界面一律照旧回根。配置字段 `returnToRoot`：`"immediately"`、`"10m"`、`"never"`，空值即默认 10 分钟；旧版本不认识这个字段会忽略它，无需升级 schema 版本（[storage.md](storage.md) §2.2 的做法）。

## 3. 呼出时的判断

依次检查，任何一条不满足就回到根（并对保留的界面发 `ViewClosed`）：

| 条件 | 回根的原因 |
|------|-----------|
| 隐藏时栈顶界面没有 `KeepOnHide`，或在根搜索 | 与现在一样 |
| 设置为"立即" | 用户关掉了这个功能 |
| 设置为"10 分钟后"且隐藏超过 10 分钟 | 太久了，用户多半已经要做别的事 |
| 这次呼出读到了**新的、非空的选中文字**（[selected-text.md](selected-text.md)） | 用户选了文字再呼出，是想对它做事；根搜索顶部显示"选中的文字"分组 |
| 用"选中文字"专用热键呼出 | 同上，即使没读到文字（会提示"没有读到选中的文字"） |
| 用命令热键 / 通知 / `Ctrl+J` 打开某个命令或任务 | 这些入口本来就先回根再打开（`OpenCommand`、`OpenTasks`），不受影响 |
| 栈里任何一层的插件被禁用或已不存在 | 界面已经不能用了 |
| 插件拒绝恢复：重新请求栈顶界面（`ViewRequest.Restore = true`）返回错误 | 例如对话已被删除、AI 已关闭 |

选中文字是**异步读取**的（预算 250ms）：如果恢复之后文字才读到，而用户还没有在恢复的界面里按键或打字，就切回根搜索；用户已经开始操作就不再打断。

上下文感知（资源管理器文件夹等）照常捕获；它的分组只在根搜索显示，所以在恢复的界面里看不到，按 `Esc` 回到根时根搜索重新运行，带上本次的上下文。页脚的上下文 chip 照常显示。

## 4. 插件如何拒绝恢复

恢复时宿主**重新请求栈顶界面**，`ViewRequest` 与当初相同（同一个 `Instance`、`Payload`、搜索文字），只多了 `Restore: true`。

- 返回错误 → 回到根，保留的界面全部收到 `ViewClosed`。错误不显示给用户（没有 toast），只写日志。
- 正常返回 → 用新内容显示（例如答案在隐藏期间写完了）。

下层界面不重新请求；用户按 `Esc` 返回到它们时照常刷新（与现在一样）。

## 5. 恢复后的界面

- 页脚在标题旁显示一个提示 "Esc 回到主界面"（点击即回到根搜索）。只在这次呼出、且仍停在恢复的那个界面时显示；离开（返回、进入下一层）或下次呼出后消失。
- 栈深为 1 时提示是"Esc 回到主界面"；更深时是"Esc 返回"（`Esc` 照常只退一层）。界面自己接管了 `Esc`（AI 正在写答案时 `Esc` 是"停止"）、搜索框里有文字（`Esc` 先清空文字）、或动作面板打开时不显示提示。
- `Esc` 的行为**不变**：有文字先清空文字，再按退一层；在栈底那层（深度 1）按 `Esc` 就回到根搜索。所以"快速回主界面"就是现有语义，不新增按键。

## 6. AI 对话

- 对话界面（`builtin.ai` 的 `chat`）设置 `KeepOnHide`；首次使用的"打开 AI"提示界面不设置。
- **R59 空闲释放**：对话的 CLI 进程 3 分钟无消息就停止，对话本身留在内存（`chats`）和实例映射（`views`）里，因为界面没有关闭（没有 `ViewClosed`）。恢复时重新请求界面，直接从内存渲染；下一条消息照常 resume 会话。窗口隐藏 10 分钟后的 `releaseIdle` 只释放被界面显示着的对话的进程，不从内存删除它们——保留的界面属于"显示着"，所以同样能恢复。
- **隐藏期间仍在写答案**：答案继续写（`Host.Render` 推送照常应用到保留的栈中的那个实例），重新呼出时显示当时的状态；如果还在写，`Esc` 仍是"停止"。
- **拒绝恢复**：`Restore` 请求时，如果这个实例对应的对话已被删除（对话记录里删除，`forget` 会去掉实例映射）、或 AI 已关闭（`enabled` 偏好为假），返回错误 → 回到根。注意：不能像首次打开那样按 payload 重新建对话，否则会把第一条消息再发一遍。

## 7. 其他候选界面（暂不开启）

| 界面 | 是否值得 | 备注 |
|------|---------|------|
| AI 对话记录（`history`） | 可以考虑 | 列表很快就能重新打开，收益小 |
| 进程管理器 | 可以考虑 | 刷新计时器在隐藏时停、显示时恢复，已具备条件；但进程列表变化快，回到旧过滤结果可能让人困惑 |
| 计时器 / 世界时钟 | 收益小 | 一个命令就能打开 |
| Ping 等网络工具 | 不适合 | 隐藏时停止 ping（`EventWindowHidden`） |
| 表单 | 视情况 | 长表单填到一半被打断时有用，以后按插件需要开启 |

## 8. 实现位置

- `pkg/plugin`：`View.KeepOnHide`、`ViewRequest.Restore`。
- `internal/config`：`Config.ReturnToRoot` 和 `EffectiveReturnToRoot` / `KeepDuration`。
- `internal/core`：`Controller.Hidden()` 记录；`Controller.Show(ctx, ShowOptions{Root})` 决定恢复还是回根（`Reset` 不变，仍是无条件回根）；`contextChanged` 处理恢复后才读到的选中文字；`Snapshot.Hint` 是页脚提示；`Controller.PopToRoot` 给提示的点击用。
- `internal/ui`：`Launcher.Shown(forSelection)` 调 `Controller.Show`，`Launcher.Hidden()` 调 `Controller.Hidden`；页脚提示（`Snapshot.Hint`，Esc 键帽 + 文字，可点击）；设置 › 通用的三段选择（立即 / 10 分钟后 / 从不）。
- `internal/shell`：窗口 `OnHide` 时调用 `Launcher.Hidden()`；选中文字热键呼出时传 `forSelection`。
- `glctl session`：新增 `hide`、`reopen [root]` 两个步骤，可以在会话里模拟隐藏再呼出（`root` 相当于选中文字热键）；文本输出多一行 `hint:`。

## 修订：有未发送的草稿时留在原界面（R76，2026-10-16）

- **你的决定**：保留的界面里输入框有未发送的文字（草稿）时，新的选中文字不会把你带回主界面。
- **两种情况都适用**：
  - 打开前就读到了选中文字；
  - 恢复后才读到。
- **不变的情况**：
  - 只有空白字符不算草稿；
  - 用"选中文字"专用热键打开，是明确的意图，仍然回到主界面。
- **实现**：`Controller.hasDraft()`（`internal/core/keep.go`），用在 `restorable` 和 `selectionOverRestore`。
- **测试**：`TestKeepSelectionGoesToRoot` 新增 4 个子测试；其中两个草稿用例在旧代码上会失败。
