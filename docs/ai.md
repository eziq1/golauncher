# 接入大模型：能做什么（方案草稿）

> 状态：提案 v0 · 2026-10-15 · 对应需求 R42（见 [requirements.md](requirements.md)）。还没有确认，等你选定范围和模型服务商后再细化。

## 1. 为什么 golauncher 适合接大模型

- **它本来就是"一句话 → 一个动作"的入口**：按 Alt+Space 输入一句话，正好就是向大模型提问的姿势。
- **插件系统就是现成的工具清单**：每个插件的命令和动作都有标题、参数，类型也明确（`ActionDo`）。破坏性的动作已经标了 `Destructive`，宿主会统一弹确认框。把它们暴露给模型作为工具（function calling），模型就能"替你点按钮"，而且危险操作仍然要你确认。
- **有环境感知**（R25）：知道当前的 Explorer 文件夹和选中的文件，可以作为上下文发给模型。
- **有推送式渲染**（`Host.Render`）和后台任务：适合流式显示回答，以及跑耗时的多步任务。

## 2. 能做什么（按价值和难度排列）

### 2.1 快速问答（Quick AI）

- 输入任意问题，按 `Tab`，或者在没有好结果时选"Ask AI"，在详情面板里**流式**显示回答。
- 可以接着追问，形成对话。回答可以复制、粘贴到前一个窗口，或存进剪贴板历史。
- 只在你明确触发时才调用模型，**打字过程中从不调用**（省钱、不泄露、不拖慢搜索）。

### 2.2 AI 命令（对文本做事）

- 对**选中的文本或剪贴板内容**执行预设的提示词：翻译（中↔英）、润色、改写语气、总结、解释代码、修语法、生成提交说明、表格转 Markdown……
- 结果可以直接粘贴回原来的窗口，替换选中的文本。
- 你可以自己写命令，提示词模板里能用 `{selection}`、`{clipboard}`、`{argument}` 等变量。每条命令都是普通命令，可以设别名和全局快捷键。这对应 Raycast 的 AI Commands。

### 2.3 自然语言操作启动器（Agent，调用插件）

- 例如：
  - "东京现在几点，和北京差几个小时" → 世界时钟；
  - "把 WSL 关了" → 终端插件；
  - "升级所有 winget 软件" → WinGet 插件，弹确认框；
  - "8080 端口被谁占了" → 网络工具；
  - "打开蓝牙设置" → 设置直达。
- 实现上，每个插件的命令和动作转成工具描述交给模型，模型选择并填参数，宿主执行。破坏性动作照旧确认，长任务进后台任务。
- 第三方插件只要按 SDK 写，就自动获得这个能力，**插件作者不用为 AI 写任何代码**。

### 2.4 结合环境感知

- 在 Explorer 里：
  - "总结这个文件夹里的文档"；
  - "这个文件是什么"（选中一个文件）；
  - "把这些照片按日期重命名"：模型先给出计划，你确认后执行。
- 发给模型的内容会先列出来（哪些文件名、哪些文件内容），默认不自动附带。

### 2.5 更聪明的搜索

- 搜索结果很差时，用模型理解意图：例如"改壁纸"→ 个性化 › 背景设置页，"电脑卡"→ 任务管理器、资源监视器。
- 也可以先用**本地的向量模型**给设置页和命令做语义索引，不联网、不花钱。可以作为后续一步。

### 2.6 剪贴板历史和计算器的增强

- 按意思搜剪贴板历史："上周复制的那个快递单号"；从剪贴板内容里提取信息（地址、电话、日期）。
- 用自然语言算东西："一年后 5 万存款按 2.1% 利息是多少"。现有的计算器能算的仍然本地算，算不了的才交给模型。

### 2.7 和其他 Agent 互通（MCP）

- **作为 MCP 服务器**：把 golauncher 的插件（应用、文件搜索、WinGet、终端、系统设置……）通过 MCP 暴露给 Claude Code、Claude Desktop 等 Agent 使用。`glctl` 已经是给 Agent 用的 CLI，这是它的自然延伸。
- **作为 MCP 客户端**：AI 对话里可以调用你配置的 MCP 服务器，例如 GitHub、日历、笔记。

## 3. 设计要点

- **模型服务商可选**：
  - Anthropic（Claude）；
  - OpenAI 兼容接口，覆盖 OpenAI、DeepSeek、通义千问、Kimi、智谱、硅基流动等；
  - 本地的 Ollama / LM Studio。

  做成一个 `ai` 抽象层，插件通过 SDK 的新接口（如 `Host.AI()`）调用，不直接访问网络。
- **API Key**：存进 Windows 凭据管理器（已有的 `password` 偏好机制），不进 `config.json`。
- **隐私**：默认什么都不自动发送；附带的上下文（选中文本、文件、剪贴板）在发送前可见。剪贴板历史里标为敏感的内容（例如密码，见 R37 的 `WriteSecret`）永远不发。提供"只用本地模型"的开关。
- **流式与取消**：回答通过 `Host.Render` 流式推送；按 Esc 或关闭视图就取消请求。
- **测试**：`glctl` 的假环境里用脚本化的假模型（固定回答和工具调用序列），不联网、可重复；真实调用只在设了环境变量时运行。
- **费用和用量**：设置里显示本月的调用次数和 token 数，可以设上限。

## 4. 建议的分期

| 阶段 | 内容 | 说明 |
|------|------|------|
| 一 | `ai` 抽象层（Anthropic、OpenAI 兼容、Ollama）+ 快速问答（2.1）+ AI 命令（2.2） | 价值最高、风险最低，不涉及替你执行操作 |
| 二 | Agent 调用插件（2.3）+ 结合环境感知（2.4） | 需要设计工具描述、确认流程、多步计划的界面 |
| 三 | MCP 服务器/客户端（2.7）、语义搜索（2.5）、剪贴板和计算器增强（2.6） | 按需要挑着做 |

## 5. 需要你决定

1. 先做哪些（建议从第一阶段开始）。
2. 主要用哪家的模型？是否需要国内服务商，或者本地模型？
3. 默认的触发方式：`Tab` 进入 AI，还是只在没有结果时显示"Ask AI"，还是两者都要。

## 6. 不通过 API，和桌面上的 Claude / ChatGPT 应用联动（R43）

不用 API Key、用你自己的订阅，有四种方式，按可靠程度排列：

| 方式 | 方向 | 在启动器里能看到回答吗 | 说明 |
|------|------|------------------------|------|
| **调用官方 CLI**：Claude Code 的 `claude -p`，OpenAI Codex 的 `codex exec` | 启动器 → 模型 | **能**，流式显示（`claude -p --output-format stream-json`） | 用 CLI 登录的订阅，不用 API Key。CLI 本身是编程 Agent，要关掉它的工具（只问答，不改文件、不跑命令）。每次启动需要几秒；用量计入订阅额度。没装 CLI 时这个方式不出现 |
| **MCP**：golauncher 作为本地 MCP 服务器 | Claude 应用 → 启动器 | 不需要（在 Claude 应用里对话） | Claude 桌面版支持本地 MCP 服务器（`claude_desktop_config.json`）。在 Claude 应用里就能让 Claude 用启动器的插件：搜文件、开应用、查端口、WinGet 安装……破坏性操作仍在启动器这边确认。ChatGPT 目前主要支持远程 MCP（开发者模式的连接器），连接本地服务器需要额外桥接，要另外调研 |
| **深链接 / 预填问题**：`claude://`（Claude 桌面版注册的协议）、`https://claude.ai/new?q=…`、`https://chatgpt.com/?q=…` | 启动器 → 应用 | 不能，回答在对方应用里 | 把问题或选中的文本带过去，开一个新对话。桌面应用对预填参数的支持需要实测 |
| **界面自动化**：激活应用窗口、粘贴、回车 | 启动器 → 应用 | 不能可靠读回 | 应用一更新就可能失效，不建议作为主要方式 |

- **快捷键冲突**：ChatGPT 的 Windows 桌面版默认用 `Alt+Space` 呼出小窗，与 golauncher 的默认热键相同。两个都装时要改其中一个；golauncher 检测到注册热键失败时应该提示。
- **建议组合**：
  - 用 CLI 在启动器里直接得到简短回答；
  - 用深链接把长对话交给 Claude 或 ChatGPT 应用继续；
  - 用 MCP 让 Claude 应用反过来使用启动器的插件。

  三者都不需要 API Key，可以和 §4 的 API 方式并存，在设置里选一个"默认 AI"。
### 6.1 CLI 方式下保留会话

两个 CLI 都能接着之前的会话继续（按本机安装的版本的 `--help` 核对过）：

- **Claude Code**：
  - 新会话用 `claude -p "…" --session-id <uuid>`，ID 由启动器生成；
  - 追问用 `claude -p "…" --resume <uuid>`；
  - 也可以从 `--output-format json` 或 `stream-json` 的输出里读 `session_id`；
  - `--fork-session` 可以从某个历史点分出新会话；
  - 不想留记录时用 `--no-session-persistence`。
- **Codex**：`codex exec resume <SESSION_ID> "…"`，或用 `--last` 接最近的一个；`--json` 输出事件流。
- **怎么接进启动器**：
  - 每个 AI 对话视图对应一个会话 ID，保存在插件存储里，所以关掉启动器、重启电脑后还能在"AI 对话历史"里打开接着聊；
  - 每次追问都是一次新的 CLI 进程加 `--resume`，上下文由 CLI 从本地会话记录里恢复；
  - 每次要重新启动进程（几秒），所以适合"问一句、看一段"的节奏，不适合逐字实时对话。
- **工作目录要单独用一个**：Claude Code 的会话按工作目录归档（`~/.claude/projects/<目录>`），`--continue` 也是按目录找"最近的会话"。启动器固定在 `%LOCALAPPDATA%\golauncher\ai\` 下运行 CLI，这样不会和你平时写代码的会话混在一起；也只用显式的 `--resume <id>`，不用 `--continue`。
- **只问答，不动电脑**：用 `--tools ""`（不给任何工具）或只给只读的工具，权限模式不跳过确认；Codex 用 `--sandbox read-only`。
### 6.2 常驻后台的 Claude 进程，以及怎么调用工具

**常驻进程**：`claude -p --input-format stream-json --output-format stream-json`（加 `--include-partial-messages` 可以逐字输出）。

- 进程启动后一直运行。用户的每条消息以一行 JSON 写进它的 stdin，回答以 JSONL 事件从 stdout 流出，同一个进程里可以连续多轮。
- 只有第一次要几秒启动，之后的追问没有启动开销。Claude Agent SDK 就是这样驱动 CLI 的。
- **生命周期**：golauncher 第一次用 AI 时启动它，放进 Job Object 跟随启动器退出，闲置一段时间后关掉（和 R41 的"闲置释放"同一个思路）。下次用时带 `--resume <会话ID>` 重启，对话不丢。
- `--bg` 是另一回事：它开的是给人 `claude attach` 进去用的后台交互会话，不适合程序对接。
- **风险**：stream-json 的消息格式不像公开 API 那样有严格的版本承诺。实现时要锁定已验证的 CLI 版本范围，解析失败时退回"每轮一个进程"的方式。

**怎么调用工具**：

1. **Claude Code 自带的工具**（读文件、搜索、Bash、WebSearch……）用 `--tools` 和 `--allowedTools`/`--disallowedTools` 控制。启动器的问答场景默认只给只读的或干脆不给（`--tools ""`）。
2. **启动器自己的能力**通过 MCP 提供：
   - golauncher 提供一个 MCP 服务器（stdio，例如 `golauncher mcp`），把插件的命令和动作暴露成工具；
   - 启动 CLI 时用 `--mcp-config` 指定它，加 `--strict-mcp-config` 只用这一个，不加载你平时给 Claude Code 配的其他 MCP 服务器；
   - Claude 想"打开蓝牙设置""查 8080 端口""用 winget 装 7zip"时，就调用这些工具，由 golauncher 执行。

   这和 §6 里"给 Claude 桌面版用的 MCP 服务器"是**同一个服务器**，做一次两处用。
3. **确认**：
   - 工具调用需要授权时，`--permission-prompts host` 加 `--permission-prompt-tool` 会把授权请求交给宿主，也就是 golauncher；
   - golauncher 用它已有的确认框问你，按你的选择回复允许或拒绝；
   - 破坏性的插件动作（卸载、关机、清空回收站）就算 Claude 有权限调用，执行前仍会弹 golauncher 自己的确认框。
4. **结果显示**：工具调用和结果都在事件流里。启动器的 AI 对话视图把它们显示成步骤，例如"🔧 查询端口 8080 → node.exe (PID 4242)"，你能看到 Claude 做了什么。
